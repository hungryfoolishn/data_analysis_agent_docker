# A1.4.2 — Worker Job Contract Security Notes (A1.4.2.1)

## 1. Contract boundary

`WorkerJob` (`langgraph_langchain/execution/job_contract.py`) is the portable,
serializable contract: JSON-safe fields, validated relative artifact paths
(absolute paths, `..`, and empty segments rejected), timeout clamped to
[default 60s, max 3600s], and an `ArtifactPolicy` extension allow-list.

`ProcessWorkerJob` extends `WorkerJob` with `namespace: dict[str, Any]`.

## 2. Process-only namespace is NOT portable

The `namespace` field exists solely for backward compatibility with the current
fork-based `IsolatedPythonExecutor`: V1/V2 namespaces hold live Python objects
(modules, classes, closures, DataFrames) inherited through fork. It cannot be
serialized and MUST NOT be advertised as part of the portable job contract.

The Docker backend does not accept a process-only namespace; any future container
backend must define its own data-passing contract (files / artifact references),
never shared in-memory namespaces.

## 3. Backend security posture

| Backend | Isolation posture |
|---|---|
| `ProcessWorkerBackend` (default) | No network, filesystem, resource, or container isolation. Capabilities advertise all isolation flags as `false`. Fork-inherited memory and shared namespace risks remain. |
| `DockerWorkerBackend` (stub) | Fail-closed: no container creation, no Docker socket access, execute/cancel raise `UnsupportedBackendError`, health reports `not_implemented`. |

Process Backend remains the default execution backend. Docker Backend is not enabled
in production. No Docker production execution path was introduced in A1.4.2.1.

## 4. Dispatcher safety properties

- No implicit backend fallback: invalid backend selection raises; Docker backend
  selection yields FAILED + `BACKEND_UNSUPPORTED`.
- Job state machine is in-memory: `VALIDATING -> QUEUED -> RUNNING -> final`.
- Duplicate active job ids rejected (`DuplicateJobError`).
- `cancel()` idempotent; pre-dispatch cancellation returns CANCELLED; post-completion
  cancellation does not rewrite succeeded to cancelled (A1.3 race contract preserved).
- Backend result `job_id` mismatch is converted to FAILED + `INTERNAL` rather than
  being accepted silently.

## 5. Explicit non-goals of this phase

- No container isolation. A1.4.2.1 does NOT make the Worker a production-grade
  security sandbox.
- No Runtime V2 default routing change; `RUNTIME_V2_ENABLED` default unchanged.
- No change to Agent prompts, planner, Evidence, or B11 frozen contracts.
- V1 is preserved.

## 6. Residual risks (carried into A1.4.2.2)

1. Fork-based process execution inherits parent memory; untrusted code can read
   in-process state.
2. No network or filesystem isolation on the Process Backend.
3. `ArtifactPolicy` default allow-list is intentionally broad for compatibility;
   container-phase policy must be tightened.
4. Docker backend is a stub; any orchestration code that tries to use it will fail
   closed (by design) until A1.4.2.2 implements the real backend.
