# A1.4.2 — Python Worker Threat Model

- Date: 2026-11-20
- Status: A1.4.2.0 architecture baseline
- Scope: Python analysis execution from `python_repl`, `PythonTaskExecutor` and `IsolatedPythonExecutor`
- Current implementation: child process inside the main API container
- Target implementation: job-scoped, non-root, low-capability Docker worker container

## 1. Trust assumptions and attacker model

The Python code executed by the analysis agent is treated as **untrusted**. An attacker may:

- submit or induce arbitrary Python code;
- import installed modules;
- use reflection, dynamic import, string construction, subprocess and native libraries;
- create child processes and background threads;
- allocate memory, write files and open sockets;
- generate ordinary analysis artifacts as well as malicious files;
- retain state across Python steps if the current namespace mechanism permits it.

The attacker is not assumed to have:

- host shell access;
- Docker Engine API credentials;
- privileged container start capability;
- control over the API authorization layer.

All adversarial validation must be performed only in an isolated test environment.

## 2. Trust boundaries

```
User
  -> API authorization/session boundary
  -> Runtime selection and plan boundary
  -> Worker Job Contract boundary
  -> Container boundary
  -> Filesystem boundary
  -> Network boundary
  -> Artifact validation boundary
  -> Approved runtime/artifact store
```

Current weaknesses at these boundaries:

- Runtime V1/V2 and worker run inside one container.
- Job Contract does not exist; the current request contains raw code and workspace paths.
- Filesystem boundaries rely on Python audit hook and path helpers.
- Network is not default-denied in production.
- Artifact validation is incomplete.

## 3. Threat register

Severity: P0 Critical, P1 High, P2 Medium, P3 Low.

### T1 — Arbitrary command execution

| Field | Assessment |
|---|---|
| Attacker capability | Python code execution |
| Preconditions | Worker receives attacker-controlled or model-generated code |
| Attack path | `subprocess`, `os.system`, `os.popen`, `os.exec*`, dynamic import, `ctypes`, shell command |
| Current protection | V1 regex may reject simple literals; worker process is non-root; A1.3.2 test container drops capabilities |
| Evidence | `langgraph_agent.py:1071-1096`; runtime probe `subprocess.run(["id"])` succeeded as uid 999 |
| Residual risk | Current: command execution is practical. Target: command can run only inside disposable worker, with limited mounts/network/resources |
| Severity | P0 today |
| Target protection | Independent low-capability worker container; no API code/secret mounts; default-deny egress; resource limits |
| Acceptance | Adversarial command test cannot access API files, secrets, host files or unauthorized services; result/artifact validation passes |

### T2 — Host/container file disclosure

| Field | Assessment |
|---|---|
| Attacker capability | Python file and OS APIs |
| Preconditions | Worker can bypass Python audit hook or inherit accessible mount |
| Attack path | `subprocess`, `ctypes`, symlink traversal, reading `/proc`, code directory, `.env`, other session workspace |
| Current protection | Python audit hook blocks direct `open()` to sensitive paths; environment cleanup; uid 999 limits some access |
| Evidence | `python_executor.py:91-121`; probes: direct `open()` blocked, subprocess bypass succeeded |
| Residual risk | P0 today due to F2; production mounts application code and all sessions read/write |
| Target protection | Mount namespace containing only read-only job input and controlled job output; no code/config/secret volume |
| Acceptance | Reads outside job input fail; code, config, Docker socket, host secrets and sibling sessions inaccessible |

### T3 — File tampering

| Field | Assessment |
|---|---|
| Attacker capability | Python file APIs or subprocess |
| Preconditions | Writable path is reachable |
| Attack path | Modify code, UI, logs, other session files, artifact store, Docker-related files |
| Current protection | Workspace helpers prefer session paths; audit hook restricts direct write; no Docker socket |
| Evidence | `python_executor.py:35-42,91-121,149-205` |
| Residual risk | P1 today: bypassing audit hook can write production bind mounts shared with uid 999 |
| Target protection | Read-only code/input mounts, per-job controlled output, no shared artifact store, parent-side copy after validation |
| Acceptance | Writes outside output fail; existing files unchanged; output cannot point to another session |

### T4 — Network lateral movement

| Field | Assessment |
|---|---|
| Attacker capability | Python socket or subprocess |
| Preconditions | Network namespace permits route |
| Attack path | Reach API, database, Redis, internal service, other container, host service or public endpoint; use DNS/IPv6/proxy bypass |
| Current protection | None in production; A1.3.2 test subnet has a host DOCKER-USER outbound restriction |
| Evidence | `docker inspect deepanalyze`; DOCKER-USER rules; worker probe connected to `127.0.0.1:8888` |
| Residual risk | P1 today |
| Target protection | Default deny egress; explicit service allow-list only; no proxy env inheritance; IPv4/IPv6 tested |
| Acceptance | Unauthorized target connections fail; authorized service access succeeds; restart persistence proven |

### T5 — Container escape

| Field | Assessment |
|---|---|
| Attacker capability | Python execution plus installed libraries |
| Preconditions | Dangerous capability, socket, device or vulnerable kernel/runtime |
| Attack path | Privilege escalation, mounted host file/device abuse, container runtime/kernel exploit |
| Current protection | No Docker socket; production starts root then drops to telebi; no cap-drop/no-new-privileges/seccomp in production; test container is stronger |
| Evidence | `docker inspect`; `docker-compose.yml`; `docker-compose.a132.yml`; `docker-entrypoint.sh:8-11` |
| Residual risk | P1 today due to production hardening gap; common Docker remains kernel-sharing, not a strong adversary boundary |
| Target protection | Non-root, cap-drop ALL plus explicit minimum additions, no-new-privileges, curated seccomp, no dangerous mounts/devices, immutable image |
| Acceptance | Configuration inspection plus isolated capability/device/socket negative tests; no privilege gain |

### T6 — Resource exhaustion

| Field | Assessment |
|---|---|
| Attacker capability | Python code execution |
| Preconditions | Missing or ineffective limits |
| Attack path | Infinite loop, fork bomb, large allocation, huge file, long block, descriptor exhaustion, detached descendants |
| Current protection | Per-call timeout/cancel, optional RLIMIT_AS, A1.3.2 test container limits; production has none |
| Evidence | `python_executor.py:150-156,264-303`; production container inspect |
| Residual risk | P1 today in production; double-fork descendants not fully proven terminated |
| Target protection | CPU/memory/PID/storage/output limits, deadline, process/container teardown, bounded queue |
| Acceptance | Resource pressure tests are contained and do not affect main service |

### T7 — Multi-tenant/session isolation failure

| Field | Assessment |
|---|---|
| Attacker capability | Filesystem APIs, symlink creation |
| Preconditions | Shared workspace parent or shared uid/mount |
| Attack path | Read/write sibling workspace, register sibling file as artifact, inherit state from wrong job |
| Current protection | Session workspace path and Python audit hook |
| Evidence | `/app/workspace` is one shared production bind mount; audit hook only in-process |
| Residual risk | P1 today |
| Target protection | Per-job input/output directories, unique non-path-safe IDs, parent path validation, no cross-session mount |
| Acceptance | Cross-session read/write/register attempts fail |

### T8 — Credential disclosure

| Field | Assessment |
|---|---|
| Attacker capability | Python introspection, file access, subprocess |
| Preconditions | Secret exists in child address space, environment, mounted file or reachable service |
| Attack path | Read `sys.modules`/module globals inherited by fork, read `.env`, access database/API service |
| Current protection | `os.environ.clear()`; direct `.env` `open()` blocked; no Docker socket |
| Evidence | `python_executor.py:139-141,112-113`; fork memory probe exposed simulated parent global |
| Residual risk | P0 today due to fork memory exposure |
| Target protection | Separate worker image/container; no parent secrets; explicit per-job variables; OS-level mount deny; secrets only in main service |
| Acceptance | Environment/config/heap scans find no API/LLM/DB credentials; secret-bearing modules absent |

### T9 — Cancellation bypass

| Field | Assessment |
|---|---|
| Attacker capability | Python process creation and signal handling |
| Preconditions | Worker can fork/setsid and escape kill group |
| Attack path | Spawn detached descendant, ignore SIGTERM, create long-running process |
| Current protection | `setsid` + killpg SIGTERM/SIGKILL; tests prove ordinary `subprocess.Popen` child termination |
| Evidence | `python_executor.py:137-138,264-303`; `tests/runtime_v2/test_a132_linux_worker_validation.py` |
| Residual risk | P2 in current design; must be re-evaluated with container lifecycle |
| Target protection | Container stop/kill is authoritative; all container descendants die with PID namespace; cleanup failure tracked |
| Acceptance | Cancel/timeout leaves no container or descendant; state and output cleanup complete |

### T10 — Artifact pollution

| Field | Assessment |
|---|---|
| Attacker capability | Generate arbitrary files or symlinks |
| Preconditions | Parent trusts worker-generated relative path |
| Attack path | Path traversal, symlink to sibling session, oversized output, executable/type confusion, malformed filename |
| Current protection | Worker-generated list excludes dot directories and enforces size; parent resolves and hashes path |
| Evidence | `python_executor.py:157-205`; `runtime/context.py:1114-1141` |
| Residual risk | P2 today |
| Target protection | Worker writes only isolated output volume; parent validates relative path, regular-file type, no symlink, size/type/quota; copies to approved store |
| Acceptance | Malicious path/symlink/oversized/type-confused outputs rejected and never enter official storage |

## 4. Risk summary

| Threat | Current severity | Blocking target architecture issue |
|---|---:|---|
| T1 Arbitrary command execution | P0 | worker not containerized |
| T2 File disclosure | P0 | audit hook bypassable; overbroad mounts |
| T3 File tampering | P1 | production code/workspace mounts writable |
| T4 Network lateral movement | P1 | no production default-deny egress |
| T5 Container escape | P1 | production hardening absent; Docker is kernel-sharing |
| T6 Resource exhaustion | P1 | production limits absent; RLIMIT often disabled |
| T7 Session isolation | P1 | shared workspace parent/mount |
| T8 Credential disclosure | P0 | fork memory exposes parent globals |
| T9 Cancellation bypass | P2 | container PID namespace should become authoritative |
| T10 Artifact pollution | P2 | no independent artifact validator |

The target architecture must address T1/T2/T8 as minimum blocking requirements for production readiness.
