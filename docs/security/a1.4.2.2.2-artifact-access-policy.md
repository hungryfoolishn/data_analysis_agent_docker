# A1.4.2.2.2 — Artifact Access Policy

## Principle

A worker may access only the files explicitly staged into its own one-shot job workspace and may publish only explicitly declared artifact bytes that pass validation.

## Matrix

| Actor | Path | Mode | Policy |
|---|---|---|---|
| Manager | `/tmp/deepanalyze-worker-jobs/<job_id>/` | full access | trusted owner and lifecycle controller |
| Manager | other job root | none | forbidden outside job-id-bound cleanup |
| Worker | `/workspace/input` | read-only | authorized staged inputs only |
| Worker | `/workspace/output` | read/write | working/output directory only |
| Worker | `/workspace/tmp` | read/write | optional ephemeral tmp |
| Worker | host originals | none | never mounted |
| Worker | other job workspaces | none | never mounted |
| Container archive | output tree | read by manager | regular files only; symlink/link members rejected |
| Publication | `collected/` | manager write | validated all-or-nothing atomic publish |

## Allowed Paths

- `/workspace/input/job.json`
- explicitly staged authorized input files
- `/workspace/output/**` for worker output
- `/workspace/tmp/**` when mounted

## Prohibited Paths

- host original input directories;
- other job roots;
- unmanaged workspace roots;
- paths outside the container's mounted job boundary;
- absolute or traversal names in artifact publication;
- dotfiles and unsafe names in publication.

## Artifact Publication Rules

1. Artifact name must be a safe relative path.
2. Names must be unique.
3. Dotfiles are rejected.
4. Declared SHA-256 and size must match.
5. Total artifact bytes must not exceed the collection quota.
6. All artifacts publish together or not at all.

## Input Rules

1. Input paths are joined through the unified safe join function.
2. Inputs are copied, never hardlinked.
3. Input mode and ownership are normalized.
4. Integrity is verified before output acceptance.

## Cleanup Rules

1. Cleanup requires job identity and manifest.
2. Cleanup refuses symlinked or escaping roots.
3. Cleanup is idempotent.
4. Unrelated workspaces are preserved.

## Violations

Any violation fails the job or rejects the affected artifact; it must never be silently repaired or guessed.

## Production Restriction

This policy applies to the Docker Worker implementation. It does not authorize production enablement.
