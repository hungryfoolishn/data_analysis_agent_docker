# A1.4.2.2.2 — Filesystem Artifact Threat Model

## Asset

Per-job Docker Worker file boundary.

## Trust Boundary

- Manager: trusted host process.
- Worker container: untrusted user code.
- Docker daemon: privileged infrastructure, not assumed malicious.
- Host filesystem: contains original inputs and other job workspaces.

## Assets and Attack Surface

| Surface | Asset | Threat |
|---|---|---|
| `/workspace/input` | staged inputs | mutation, traversal, symlink substitution |
| `/workspace/output` | produced artifacts | escape, hidden or unsafe names, oversized output |
| `/workspace/tmp` | temporary execution state | cross-job contamination |
| Docker archive | artifact transport | symlink/link member injection |
| Cleanup path | host filesystem | identity mismatch and unmanaged deletion |
| Workspace root | job isolation | reuse, impersonation, cross-job leakage |

## Threats and Controls

### T1 — Input mutation

Threat: user code changes a staged input before output verification.

Control: input mount is read-only; files are `0440 root:10001`; manager re-hashes staged files before accepting output.

### T2 — Path traversal

Threat: relative path escapes the workspace.

Control: `validate_relative_path` rejects absolute paths, traversal segments, null/control characters, non-NFC forms, and overlong names; `safe_workspace_join` refuses symlinked roots before resolution.

### T3 — Symlink escape

Threat: worker creates symlinks and links to escape output or hide host files.

Control: collect rejects symlink/link/non-regular Docker archive members; publish validates relative names and rejects dotfiles.

### T4 — Artifact substitution

Threat: collected bytes do not match declared artifact metadata.

Control: declared size and SHA-256 are checked during publication.

### T5 — Partial publication

Threat: crash or hostile artifact list leaves a partial result set.

Control: publish validates everything first, writes temporaries, atomically replaces, and rolls back on failure.

### T6 — Cross-job workspace attack

Threat: cleanup or creation affects another job.

Control: managed root is deterministic, one-shot, and cleanup requires a matching manifest and job identity.

### T7 — Resource exhaustion

Threat: oversized artifact set exhausts host disk.

Control: collection-level total-byte cap and per-file size checks.

Known limitation: filesystem-level quota/accounting is not yet implemented.

### T8 — Missing tmp mount regression

Threat: old entrypoint crashes when `/workspace/tmp` is absent.

Control: entrypoint falls back to container temp directory.

## Residual Risks

1. No network egress isolation yet.
2. No secret isolation yet.
3. Filesystem-level disk quota is unverified.
4. Docker daemon is a privileged trusted component.
5. Manager is trusted.

These are accepted as explicit boundaries for A1.4.2.2.2 and drive the next phase.
