## 1. Benchmark Design

### 1.1 Dataset

- B6 golden dataset: `tests/evaluation/data/sales_performance_2025_2026h1.csv`
  (sha256 prefix `ed9aa649d31c`, 72 rows, 18 periods × 4 departments).
- Content is byte-identical (modulo line endings) to the version frozen at
  commit `63dfe4c` whose sha256 prefix `f7ee4d6874c0` is recorded in the
  golden case JSONs.

### 1.2 Ground Truth

- All expected metric values and tolerances come from the independent B6
  golden case JSONs (`tests/evaluation/golden_cases/*.json`, 50 cases).
- Ground truth is never derived from agent output.
- Scoring uses `|actual - expected| <= tolerance`, matching the B6
  comparator semantics.

### 1.3 Ground-Truth Exclusions (documented)

| Excluded item | Reason |
|---|---|
| `trend_analysis_005`, `trend_analysis_006` (whole cases) | Frozen golden ground truth expects `monthly_revenue = 0` for Q2 2026, but the frozen dataset (sha `f7ee4d6874c0`) contains non-zero Q2 revenue rows. The golden JSON is inconsistent with its own recorded dataset version; treating 0 as correct would reward wrong answers. Flagged as a B6 golden-data quality issue. |
| `revenue_change_pct` metrics in `comprehensive_analysis.json` (12 metrics) | No `compare_period` in filters; the expectation (e.g. `0.1` for 2026-01) is not derivable from the dataset by any documented semantics (month-over-month gives `-0.2825`). Unverifiable ground truth is excluded, not scored as pass/fail. |

Effective scored set: **48 cases**, all metric expectations verifiable against
the dataset.

### 1.4 Fair-Comparison Setup

| Dimension | Single-agent | Multi-agent |
|---|---|---|
| Data | Same CSV frame | Same CSV frame |
| Analysis core | `execute_analysis_operation` (production allowlist ops) | Same |
| Evidence adapter | `collect_operation_evidence` (production evidence) | Same |
| Tool access | Identical operations | Identical operations |
| Planning | None (one-shot, B11.1 `SingleAgentRunner` semantics) | `MetricPlanPlanner`: one executor step per verifiable metric + verify step |
| Review | None | `QualityAuditorAgent` checks findings/evidence/completeness |
| Retry | None | Bounded (`max_retries=1`) |

## 3. Fault Injection (uncertainty disclosure)

`fault_missing_department`: query a department that does not exist.

| Path | Behavior |
|---|---|
| Single | Returns no value; no structured error or disclosure (disclosure rate 0.0). |
| Multi | Auditor rejects with structured issues (`no_findings`, `no_evidence`); `review_decision = reject` (disclosure rate 1.0). |

This is the concrete quality improvement: the multi-agent review loop converts
silent failures into structured, auditable uncertainty disclosure.

## 5. Honest Limitations

1. **No statistical significance claim.** 48 deterministic cases with zero
   variance; significance testing is not applicable and none is claimed.
2. **No LLM in the benchmark loop.** Both paths use the deterministic
   analysis core; token/cost metrics are N/A. This matches the B11.1
   deterministic benchmark contract, not the full LLM production path.
3. **Improvement scope.** On clean data the multi-agent path equals the
   single-agent baseline numerically; the measured improvement is limited to
   structured failure disclosure and review/evidence enforcement.
4. **Ablation study** (§9.7 of the master scope) not executed in this round;
   the review-removal ablation is implicitly covered by the single-agent
   baseline, and the fault case shows the reviewer is the component that
   provides disclosure value.

## 6. Conclusion

- Numeric correctness: no regression (gate 1 ✓).
- Evidence validity: no regression (gate 2 ✓).
- Deterministic quality improvement: fault-case disclosure 1.0 vs 0.0.
- The frozen-benchmark quality gate for B11.6 is **PASS** under the
  documented scope and exclusions, with the improvement claim limited to
  uncertainty disclosure as recorded above.
