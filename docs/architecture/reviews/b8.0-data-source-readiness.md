## 4. 数据契约现状

`FetchResult` 三段 metadata 与要求的对应关系：

| 要求字段 | FetchResult 现状 | DataAsset 现状 | 缺口 |
| --- | --- | --- | --- |
| source_id | ✅ `source_metadata.adapter_id` | `source_metadata`（自由 dict，可承载） | 无自动注册桥 |
| dataset_id | ✅ `dataset_metadata.dataset_id` | 可承载 | 同上 |
| request_parameters | ✅ `source_metadata.request` | 可承载 | 同上 |
| source_url | ✅ `dataset_metadata.source_url` | 可承载 | 同上 |
| fetched_at | ✅ `fetch_metadata.fetched_at` | 可承载 | 同上 |
| observation_period | ❌ 仅请求侧 start/end，结果未显式记录实际观察期间 | 可承载 | **契约字段缺失** |
| release_date | ❌ 无 | 可承载 | **契约字段缺失** |
| revision/version | 部分：`content_hash`（数据版本）✅；发布修订 ❌ | `content_hash` ✅ | **revision 历史缺失** |
| unit | ✅ `dataset_metadata.unit` | 可承载 | — |
| frequency | ✅ `dataset_metadata.frequency` | 可承载 | — |
| quality_report | ✅ `quality_report` 对象 | 可承载（dict 化） | — |
| content_hash | ✅ `content_hash` | ✅ 原生字段 | — |

**结论**：优先复用现有模型可行——`FetchResult` 已覆盖约 8/12 字段，`DataAsset.source_metadata`（自由 dict）可承载其余，无需新建同职责结构；缺的是 3 个显式字段（observation_period/release_date/revision）与**注册桥**本身。

## 5. Fetch / Refresh / Cache / Version 现状

- Fetch：完整（校验→缓存→重试→normalize→validate→result→回写缓存）。
- Refresh：`refresh=True` 绕过缓存 ✓；无定时任务、无刷新调度器、无更新记录。
- Cache：进程内 TTL dict；重启/多进程不共享（P2）。
- Version：逐 fetch content_hash；无版本历史、无修订追踪、无"上次刷新时间"的持久化记录。

## 6. DataAsset 注册和持久化链路

**当前不存在**。缺失环节：`AdapterRegistry.fetch(request) → FetchResult → DataAsset 构造（name/source_type="adapter"/location=None/schema_snapshot/frame 推导/source_metadata=FetchResult 三段合并）→ runtime.register_dataframe（_dataframe 路径）或独立 acquisition 持久化`。既有资产机制（`data/assets.py`、SnapshotStore、`AssetResolver`）完全可复用——FetchResult.dataframe 可走 `register_dataframe`（文件式）或为时序数据新增快照路径；这是 B8.1 的核心交付。

## 7. Runtime 接入情况

未实现。Runtime V2 消费侧已就绪（`AssetResolver` + `runtime_inputs` + OutputAssetBinding，B11.2.1/B4.2.1 契约稳定），一旦采集侧产出 DataAsset 即可无改动进入 `build_execution_request`。

## 11. 每个 Adapter 的 B8 验收标准（统一模板）

对每个 Adapter（FRED/BLS/BEA/NBS）：
1. 真实 API fetch 成功（有凭据的准生产验证，非 mock）；
2. normalize 产出符合 DatasetSpec 列契约（time_column/value/unit 对齐）；
3. QualityReport passed（无 failed issue）；
4. FetchResult → DataAsset 注册成功，source_metadata 含 source_id/dataset_id/request_parameters/source_url/fetched_at/observation_period/unit/frequency/quality_report/content_hash（+release_date/revision 当源可提供）；
5. Asset 持久化并可经 AssetResolver 恢复；
6. Runtime V2 以该资产执行至少一个确定性分析操作；
7. Evidence 关联输入资产与执行，报告披露数据来源（source_url/fetched_at/unit/frequency）。

1. B7 契约层（Adapter ABC/Registry/Catalog/FetchResult/Quality/Cache/Retry）已完整实现且有离线测试——B8.1 的桥接只需复用，不需要先修 B7；

4. 4 个真实 Adapter 已存在，B8.4 的增量是"贯通验证"而非新实现（NBS 除外）。

**前置建议**：B8.1 可立即启动；与 B4.3（Excel/Parquet e2e）和 B5 收尾无硬冲突，可并行；B6 Golden 全链路化建议先于 B8.7 验收执行（使采集产出的资产进入冻结基线）。
