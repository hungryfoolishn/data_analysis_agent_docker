## 3. Domain Pack 边界（冻结）

**属于 Macro Pack（新增 `runtime/macro/`）**：
- 指标目录（MacroIndicatorCatalog）与指标语义；
- 时间语义与转换引擎（YoY/MoM/QoQ/Annualized/Cumulative/IndexChange/RollingAvg/PeriodComparison）；
- 六类分析模板与模板选择器；
- Macro Intent Resolver（指标/国家/期间歧义解析）；
- 宏观 Evidence Requirement 与结论分类规则。

**不属于 Macro Pack（禁止实现）**：
- 数据获取（Adapter/fetch/限流/缓存）——Acquisition Platform 职责；
- 计划校验、执行调度、Binding、通用 operation——Runtime 职责；
- 财务指标语义——B10 财务 Pack；
- LLM 客户端管理——沿用 `run_analysis_stream` 注入模式。

**与 Runtime 的接缝（仅两个）**：
1. 入口：MacroIntentResolver 产出 GeneralAnalysisPlan v2 → 现有校验链 → Runtime V2；
2. 出口：转换/分析产出的 DataAsset 经现有 Binding/Evidence/Report 语义被报告引用。

## 5. 时间和版本语义（冻结）

1. **日期四分离**：`observation_period`（数据所属期间）、`observation_date`（数据点日期）、`release_date`（发布日期）、`revision_date`（修订日期）——永不合并；报告披露时必须分别呈现（toDo.md Phase 2C/3A 要求）。
2. **数据版本**：一切追溯锚定 `DataAsset.content_hash`；目录修订只改 `MacroIndicatorCatalog` 的 `profile/catalog_version`，不改历史 Observation。
3. **可比性前置条件**：YoY/MoM/QoQ 输入必须为同一 `frequency + seasonal_adjustment + price_basis + cumulative=false`（或先经转换对齐）；跨序列比较（中美 CPI）必须披露基期与口径差异（`comparability`）。
4. **发布滞后披露**：报告必须声明数据截至观察期间，实际发布晚于期间（`release_lag_days`），toDo.md 3C"发布时间滞后披露"。

## 6. 转换引擎设计（`runtime/macro/transforms.py`，B9.2）

输入：单个 `MacroObservation` 序列（从 DataAsset 经 AssetResolver 恢复的 DataFrame 构造）。输出：新 DataFrame → 经 Runtime 注册为新 DataAsset（`register_fetch_result` 同路径或 `register_dataframe`，保留 input Asset ID/参数/语义进 source_metadata），并生成 `MacroTransformResult`。

| Transform | 公式 | 输入频率要求 | 输入要求 | 缺失处理 | 语义约束 |
| --- | --- | --- | --- | --- | --- |
| YoY | (v_t / v_{t-4或12} − 1)×100（Q 用 4，M 用 12，按 frequency 定 lag） | quarterly/monthly；annual 不适用（无去年同期内样本） | level 型；growth_rate 型输入 → 拒绝（避免增长率再差分） | lag 位置缺失 → 该期结果缺失（不插值） | nsa 序列必须披露"未季调，含季节性"；sa 与 nsa 不得混算 |
| MoM / QoQ | (v_t / v_{t-1} − 1)×100 | monthly / quarterly | level 型 | 同上 | nsa 必披露季节性；sa 优先 |
| Annualized | (1+qoq)^4−1 或 (1+mom)^12−1；annual 级：×频率倍数 | quarterly/monthly | qoq/mom 结果序列（链式） | 任意期缺失 → 无法年化该期 | 声明"年化率，基于环比链式假设" |
| Cumulative | 累计和（YTD）：Σ 单期值 | monthly/quarterly | flow 型指标（GDP/出口/财政）；stock 型（CPI 指数、失业率）→ 拒绝 | 缺失期 → 累计值标记 incomplete | **中国季度 GDP 累计→单季**：单季 = 累计(t) − 累计(t−1)，且 Q1 无前季、必须以年度核查；累计序列修订会级联影响所有单季值 → 转换必须携带 `revision_policy` 披露并拒绝混合修订版本的输入 |
| Index Change | (v_t / v_base − 1)×100，base=显式参数或首期 | 任意 | level/index 型 | base 期缺失 → 全序列缺失 | 披露基期（base_period） |
| Rolling Average | mean(v_{t−k+1..t}) | 任意 | level/growth_rate | 窗口内任一缺失 → 该期缺失（不插值） | 披露窗口 k；nsa 提示季节性 |
| Period Comparison | v_period − v_base（水平差）或比率 | 任意 | 任意 | 任一侧缺失 → 该项缺失 | 输出明确标注比较双方期间 |

**Evidence 保留**：每个转换产出的 `MacroTransformResult` 写入 `source_metadata["macro_transform"]`（Runtime 注册时），转换链上的 Evidence 经现有 `collect_operation_evidence`/canonical 流程引用 input Asset ID + output Asset ID + 转换参数（`parameters` 字段）——追溯链 = 报告结论 → Evidence ID → output Asset → input Asset（原始）→ 源（source_url/fetched_at）。
**实现位置**：转换在 Runtime 之外以纯函数实现（输入 DataFrame → 输出 DataFrame），执行仍走 Runtime V2 的注册/Binding/Evidence 链路——Macro Pack 不私自执行分析（新增白名单 operation `macro_transform` 由 B9.2 注册进 `PLAN_OPERATIONS`/`analysis_operations`，属 B4.2 契约的自然扩展而非第二套执行体系）。

## 7. 六类分析模板设计（`runtime/macro/templates.py`，B9.3）

模板 = 数据契约 + 步骤编排 + 证据要求 + 报告章节声明。所有模板的分析步骤最终映射到通用 operation/`analysis_methods`（trend/correlation/compare_periods/data_quality/calculate_ratio 等），经 GeneralPlan v2 表达。

**通用结构**：`MacroTemplate{template_id, required_indicators, optional_indicators, default_transforms, plan_builder(question, resolved_assets) -> GeneralAnalysisPlan v2, evidence_requirements, output_sections, data_insufficiency_policy}`。

| 模板 | 必选指标 | 可选指标 | 默认转换 | 分析步骤（通用 operation 序列） | 必需 Evidence | 输出章节 | 数据不足处理 | 解释限制 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 GDP 增长 | gdp（us/cn，level） | 无 | 累计→单季（CN）、YoY、QoQ annualized | data_quality → 转换链（YoY）→ trend → compare_periods | 每期 YoY 值 + 原始 level 资产 | 增长概览/趋势/波动/局限 | 累计→单季披露修订级联；实际 vs 名义必须标注 price_basis | 不得由单季波动推断趋势反转 |
| 2 CPI/PPI 通胀 | cpi（us+cn，index，nsa/sa 各一） | ppi | YoY（同比口径对齐）、MoM（sa） | data_quality → YoY → MoM → compare_periods（中美） | YoY 值 + 基期披露 | 同比/环比/中美对比/局限 | 基期不一致 → 限定结论为"各自同比"而非直接指数比较 | 相关性≠因果；房价等未纳入不得推断 |
| 3 就业 | unemployment_rate / nonfarm_payrolls（us） | wage 增长 | MoM、YoY（payrolls）、level | data_quality → trend → compare_periods | 水平+变化值 | 就业水平/变化/参与率（若有数据） | 数据缺失 → 只报已有期间 | 单月波动不作趋势结论 |
| 4 利率与货币政策 | policy_rate（us Fed/CN LPR） | cpi（实际利率上下文） | level → Period Comparison | data_quality → period_comparison（加息前后）→ correlation（利率 vs 通胀，可选） | 政策利率水平 + 变化时点 | 政策路径/实际利率（若 CPI 可用）/局限 | CPI 缺失 → 不计算实际利率 | correlation 不构成因果结论（3C 规则） |
| 5 国际贸易 | exports/imports（us 或 cn） | 贸易差额（可由 export−import 派生） | YoY、Cumulative（YTD） | data_quality → YoY → calculate_ratio / 差额派生 | YoY + 差额 | 出口/进口/差额/局限 | 单边数据 → 不计算差额 | 汇率影响未剔除必须披露 |
| 6 多指标综合 | ≥2 个已注册指标 | 全部 | 各指标 YoY → Rolling Average 平滑 | 每指标 YoY → correlation（成对）→ compare_periods（基准期前后） | 每对相关系数 + 各自 YoY | 分指标/联动（相关性）/综合局限 | 任一指标数据不足 → 降级为单指标分析并披露 | 相关→因果禁令；季调/名义实际口径差异披露 |

数据不足时的统一政策：`min_observations` 不满足 → 明确"数据不足"章节 + `needs_clarification`（若为指标选择问题）或限定结论范围；**不降级为其他指标、不静默缩短期间**。

## 8. Macro Planner 集成设计（`runtime/macro/`，B9.4）

目标调用链（复用 B4.2.1 全部契约）：

```
User Goal
  → MacroIntentResolver（新，复用 FinancialSemanticResolver 的诊断标记模式：
      SEMANTIC_INDICATOR_AMBIGUOUS / SEMANTIC_COUNTRY_UNCLEAR / SEMANTIC_PERIOD_UNCLEAR）
      输出：MacroIntent{concepts, countries, period_range, transform_hints, ambiguities}
  → 歧义 → needs_clarification（PlannerResult.clarification_questions）
  → Indicator Resolution（MacroIndicatorCatalog.resolve(concept, country)）
  → Macro Context Builder（对每个 indicator：AcquisitionService.acquire(FetchRequest) 或
      复用已有 DataAsset → MacroObservation 序列 + DataProfile）
  → Template Selector（按 intent.concepts 匹配六类模板；多概念 → 多指标综合）
  → Macro Plan Builder（模板 plan_builder 产出 GeneralAnalysisPlan v2：
      转换步骤（macro_transform op，input_refs 指向指标 DataAsset，output_name 如 cpi_us_yoy）
      → 分析步骤（trend/correlation/compare_periods，input_refs 指向上游 output）
      → 报告步骤）
  → validate_general_plan v2（现有）
  → general_plan_to_runtime_plan（现有）
  → validate_runtime_plan（现有）
  → initialize_plan / Scheduler / Binding / Evidence / Report（现有 Runtime V2）
```

关键检查项回答：
- **指标歧义**："CPI" 命中 us+cn 两个 → `SEMANTIC_INDICATOR_AMBIGUOUS` → needs_clarification（要求国家），不默认选一个；
- **不可实现意图**："分析利润率"（宏观目录无该概念）→ `SEMANTIC_UNKNOWN_CONCEPT` → needs_clarification，不静默改写；
- **数据缺失**：catalog 有但 catalog 无该期间数据 / acquire 后 observations 不足 → 模板 data_insufficiency_policy → 限定结论 + 披露；
- **领域模板 → 通用 operation**：转换步骤 = `macro_transform` 白名单 operation（B9.2 注册进 `PLAN_OPERATIONS`，参数 schema 由 `_valid_parameters` 扩展——这是对 B4.2 契约的**扩展**而非第二套协议）；分析步骤 = 既有 operation；
- **上游输出**：全部经 GeneralPlanStep.output_name + `{step_id}.{output_name}` 引用 + Binding（B4.2.1 契约，零新增）；
- **规划失败**：沿用 `PlanningOutcome` 四态（`runtime/llm_planner.py`），Macro 层状态经 outcome.reason_code 传播（`macro_intent_ambiguous` 等），**禁止静默改写**；
- **Planner 协议**：MacroIntentResolver 是 `PlannerInput` 的前置扩展（注入 `session_context["macro_intent"]`），不新建 Planner 协议、不绕过 `validate_general_plan`/`validate_runtime_plan`/`initialize_plan`。

LLM 参与（B9.4+，可选增强）：MacroIntentResolver 用 LLM 解析自然语言中的指标/国家/期间（白名单约束输出 MacroIntent JSON），失败回退关键词匹配——与 B4.2.1 的注入模式一致，B9.0 只冻结接口。

## 9. Evidence 和报告设计

结论五分类（写入 `MacroEvidenceRequirement` 与模板输出章节声明）：

| 分类 | 判定 | Evidence 要求 |
| --- | --- | --- |
| Fact | 直接来自 DataAsset 的原始值（如"2026-03 美国 CPI 为 xxx"） | canonical evidence：input Asset + source_metadata（source_url/fetched_at） |
| Statistical Relationship | 经确定性 operation 计算的统计结论（YoY 值、相关系数） | 转换/分析步 canonical evidence：input Asset + 转换参数 + 输出 Asset |
| Economic Interpretation | 领域规则下的解释（如"通胀处于高位区间"） | 依赖的 Fact/Relationship Evidence + 模板解释规则 ID（解释规则本体由领域模块声明，不进通用 Runtime） |
| Hypothesis | 明确标注为假设的推断 | 引用所依据的 Fact/Relationship，标记 `hypothesis` |
| Unverified Inference | 无充分证据支撑的表述 | **禁止出现在报告**——validate/模板输出章节检查拒绝 |

追溯链（每条关键结论）：`结论 → Evidence ID → output Asset → input Asset ID → 数据版本(content_hash) → source_metadata(source_id/dataset_id/source_url/fetched_at/unit/frequency) → MacroObservation(指标定义/观察期间) → MacroTransformResult(转换参数)`。

**复用方式**：Fact/Relationship 用现有 `collect_operation_evidence` + canonical + `build_verified_report`（B8 已扩展报告引用输入资产）；`source_metadata["macro_transform"]`/`["macro_indicator"]` 由转换/注册时写入；解释与假设经 `ReportFinding.limitation_notes` + findings 的 claim 前缀标记呈现（现有 `validate_analysis_report` 契约不变）。
