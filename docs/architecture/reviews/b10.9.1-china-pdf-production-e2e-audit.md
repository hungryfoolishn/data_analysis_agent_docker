# B10.9.1 China Financial PDF Production E2E Audit

Date: 2026-11-17  
Branch: `codex/phase1-m2.4-sqlite-schema`  
Audit HEAD: `bdfb729`  
Decision: **B10.9.1 = BLOCKED**

## 1. Core Finding

**The B10.9 China PDF parser (`china_pdf.py`) is completely disconnected from the
production platform infrastructure (AcquisitionService, DataAsset, SnapshotStore,
EvidenceRegistry, FinancialDomainRuntime).** The parser works in isolation but
its output never enters the platform.

## 5. Detailed Findings

### P0: Production chain break

**Location**: `langgraph_langchain/runtime/financial/china_pdf.py` (entire module)
**Impact**: Real CNINFO PDFs can be parsed to canonical facts but cannot enter
the DataAsset/Snapshot/Runtime/Evidence system. The B10.9 acceptance document
claims "DataAsset Integration: PASS (via AcquisitionService)" but there is no
such integration in the code.

**Proof**:
```bash
grep -n "AcquisitionService\|DataAsset\|Snapshot\|Evidence" \
  langgraph_langchain/runtime/financial/china_pdf.py
# Result: no matches
```

### P1: FinancialDomainRuntime disconnected from AcquisitionService

**Location**: `langgraph_langchain/runtime/financial/runtime_integration.py` (lines 64-100)
**Impact**: `FinancialDomainRuntime.run()` requires a pre-built `FinancialContext`
with `statements` (FinancialStatement objects). There is no factory method that
loads statements from DataAssets or SnapshotStore. In platform mode, it requires
`input_asset_ids` to be provided externally.

### P1: `china_fact_to_row` is dead code in production

**Location**: `langgraph_langchain/runtime/financial/china_documents.py` (line 326)
**Impact**: This function converts `ChinaFinancialFact` to canonical row dict,
but is never called by `ChinaCompanyFilingsAdapter.normalize()` or any other
production code. The adapter expects raw facts from its transport, not from
the PDF parser.

### P1: External smoke test does not validate the platform chain

**Location**: `tests/external/financial/test_financial_china_pdf_smoke.py`
**Impact**: The test downloads a real PDF, parses it, and maps subjects - but
never calls `AcquisitionService.acquire()`, never produces a `DataAsset`, and
never verifies SnapshotStore or EvidenceRegistry. The PASS result is a
parser-only validation, not a production E2E validation.

### P1: No real-PDF golden case

**Location**: `tests/fixtures/financial/b10_golden.json`
**Impact**: All 20 golden cases use manually constructed JSON with expected
values. None are sourced from a real CNINFO PDF. There is no independent
expected-value verification for China PDF parsing.

## 9. Conclusion

**B10.9.1 = BLOCKED**

The China PDF parsing capability works correctly in isolation. However, the
production chain from PDF to Evidence is NOT connected. B10 cannot be frozen
until this chain is completed and validated with a real end-to-end test.

## 10. Required Fix Scope

To unblock B10:

1. Add a `ChinaPdfFilingsAdapter` that uses `china_pdf.py` and implements
   the B8 `HttpJsonAdapter` contract (fetch -> normalize -> validate).
2. Register it in the adapter registry and route through `AcquisitionService`.
3. Add a Golden case with real PDF input and independently verified expected values.
4. Add an E2E test: `CNINFO -> PDF -> Parser -> AcquisitionService -> DataAsset
   -> SnapshotStore -> FinancialDomainRuntime -> EvidenceRegistry -> Verified Report`.
