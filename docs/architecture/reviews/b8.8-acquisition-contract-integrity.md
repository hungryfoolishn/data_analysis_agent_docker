# B8.8 — Acquisition Contract Integrity Review

Date: 2026-11-15
Branch: `codex/phase1-m2.4-sqlite-schema`
Base: `d095c1e feat(macro): add macro domain models and indicator catalog`

## 1. Scope

B8.8 audits the acquisition contract chain
`Adapter.fetch → FetchResult → register_fetch_result → SnapshotStore → DataAsset → AssetResolver`
and hardens contract/consistency defects without changing storage engines or
adapter architecture.

## 2. Audit result (gap matrix)

| Module | Current implementation | Finding | Severity | Handling |
| --- | --- | --- | --- | --- |
| `FetchResult` | Explicit B8.1 fields; `observation_period` derived from normalized frame; `release_date`/`revision` only when upstream provides (`_release_dates` mapping / adapter field) | Unknown metadata is preserved as `None`; no fabricated release/revision dates. `fetched_at` is UTC ISO. | OK | No change |
| FRED normalize | Rows passed through in upstream order | No deterministic sort/dedup; duplicate observation rows survive. | P2 | Fixed: drop invalid dates, dedup on `(date, series_id)` (latest wins), stable sort |
| BLS normalize | Uses bare `period` label and **drops the observation year** | Rows from different years collapse to the same period key (`M01` repeated per year) — data corruption on multi-year fetches. | P1 | Fixed: period key is now `f"{year}-{period}"`; deterministic dedup/sort |
| BEA `_fetch_raw` | Sends empty `UserID` when `BEA_API_KEY` missing although the descriptor declares `requires_credentials=True` | Silent unauthenticated request instead of fail-fast. | P1 | Fixed: missing credential raises `AdapterRequestError` before transport |
| BEA normalize | Upstream order preserved | Non-deterministic ordering/dedup. | P2 | Fixed: dedup exact rows, stable sort by `(period, line_description)` |
| SEC normalize | Mixed periods sorted only implicitly | Exact duplicate facts survived; distinct accessions (revisions) must not be merged. | P2 | Fixed: collapse only exact duplicates; stable sort by `(end, start, form, accession_number)` |
| NBS normalize | Dedup before sort | Duplicate resolution depended on payload order. | P2 | Fixed: stable sort first, then keep last value per period |
| `register_fetch_result` | Dedup on `(dataset_id, content_hash)` returns existing asset | A dedup candidate whose snapshot file was lost returned an unrestorable asset. | P1 | Fixed: dedup only when the stored snapshot is restorable; otherwise a fresh snapshot-backed asset is registered |
| Snapshot/asset transaction | `save → asset → persist`, rollback deletes snapshot and asset on failure | Verified: no orphan snapshot on registration failure (mirrors `register_sqlite_result`). | OK | No change |
| `content_hash` | `FetchResult.hash_frame` (adapter layer) and `hash_dataframe` (snapshot layer) are separate stable algorithms | Both are deterministic; the two-layer hash is intentional and documented. | P3 | Documented, no change |
| Credentials | FRED `_credentials` imported an unrelated config key (dead import) | No leak, but misleading. | P3 | Removed |

Concurrent multi-process registration relies on the runtime's existing
JSON state persistence (same model as `register_sqlite_result`); it is
documented as a single-writer boundary, not re-engineered in this batch.

## 3. Registration bridge transaction model

1. Dedup scan: existing asset with same `dataset_id` + `content_hash` **and a
   restorable snapshot** is returned unchanged (idempotent).
2. Otherwise: new snapshot → new `DataAsset` (with full provenance metadata) →
   link to current task → persist.
3. Failure at any step removes the new asset, the task link, and the new
   snapshot; the previous asset/version state is untouched.

## 4. Tests

Offline, transport-injected (`tests/test_acquisition_contract.py`):

- FRED/BLS/BEA/SEC/NBS deterministic normalization and dedup.
- BLS multi-year period keys (`2023-M01`, `2024-M01`).
- BEA credential fail-fast before transport.
- SEC revisions preserved, exact duplicates collapsed.
- NBS dedup independent of payload order.
- Unknown `release_date`/`revision` stay `None` (not fabricated).
- Dedup candidate with deleted snapshot is not returned; a restorable asset is
  registered instead.

## 5. Remaining issues

- P3: adapter-layer and snapshot-layer content hashes are separate stable
  algorithms (`FetchResult.hash_frame`, `assets.hash_dataframe`). Kept for
  compatibility; both deterministic and verified at snapshot save time.
- P3: multi-process concurrent registration is out of scope; single-writer
  runtime state assumed (pre-existing runtime boundary).
