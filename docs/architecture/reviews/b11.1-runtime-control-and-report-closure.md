# B11.1 Runtime Control & Report Closure

Status: implemented and verified.
Baseline: B11.0 `7d1ced9`; B10.1 fix `1524c6c`.
Scope: Runtime selection integration, plan execution validation, canonical evidence, deterministic report closure, RuntimeOutcome.
Not changed: Runtime V2 default flags, Legacy ReAct, B6 Golden expectations, Adapter ingestion.

## Implemented chain

```text
Analysis request
  -> RuntimeSelectionPolicy.from_env()
  -> decide_runtime_route()
  -> _Session + prepare_file_analysis()/prepare_sqlite_analysis()
  -> General Planner
  -> General Plan Validation
  -> Runtime Plan conversion
  -> AnalysisRuntime.initialize_plan()
      -> legacy validate_plan()
      -> validate_runtime_plan()
      -> Tool Registry / Tool Schema checks
  -> Runtime V2 TaskRunner
      -> run_analysis_operation / run_sqlite_query
      -> output DataAsset / Artifact
      -> CanonicalEvidence Registry
  -> runtime.build_verified_report()
      -> validate_analysis_report()
      -> render_analysis_report()
  -> session.report
  -> runtime.build_runtime_outcome()
```

Runtime V2 remains opt-in. `RUNTIME_V2_ENABLED` and fallback defaults were not changed.

## Runtime selection

`run_analysis_stream()` now uses:

```python
policy = RuntimeSelectionPolicy.from_env()
route_decision = decide_runtime_route(policy=policy)
session.runtime_route_decision = route_decision
log_runtime_route(...)
```

Selection branches covered:

| Case | Result |
| --- | --- |
| `RUNTIME_V2_ENABLED=false` | `legacy_v1`, no fallback |
| Runtime V2 enabled and completed | `runtime_v2`, no fallback |
| Business task failure | stays `runtime_v2`, no fallback |
| Infrastructure failure + fallback enabled + strict mode | stays `runtime_v2`, no fallback |
| Infrastructure failure + fallback enabled + non-strict | `legacy_v1`, fallback true |

The real route uses `route_decision.selected_runtime`, not a direct `RUNTIME_V2_ENABLED` flag.

## Plan validation

`AnalysisRuntime.initialize_plan()` now accepts execution tools and performs two-stage validation:

1. `validate_plan()` for schema, asset, and dependency basics.
2. `validate_runtime_plan()` for:
   - tool-name allowlist when real execution tools are supplied;
   - expected outputs;
   - dependency cycles;
   - operation-specific parameters;
   - read-only SQLite SQL;
   - multi-statement rejection;
   - tool argument schema validation.

`PlanExecutionValidationError` prevents unsafe plans from reaching TaskRunner.

Planner failure no longer silently falls back to inspect/data-quality. File and SQLite workflows raise clarification/validation errors to the caller.

## Canonical Evidence

New modules:

- `langgraph_langchain/evidence/models.py`
- `langgraph_langchain/evidence/registry.py`
- `langgraph_langchain/evidence/adapters.py`

Canonical model:

```python
CanonicalEvidence(
    evidence_id="evid_...",
    evidence_type="analysis_operation" | "sqlite_query" | "legacy",
    execution_id="exec_...",
    task_id="step_...",
    tool_name="run_analysis_operation",
    input_asset_ids=["asset_..."],
    output_asset_ids=["asset_..."],
    artifact_ids=["artifact_..."],
    evidence_text="...",
    numeric_values={"row_count": 3.0},
    validation_status="unverified" | "verified" | "failed",
    source_metadata={
        "operation": "group_aggregate",
        "truncated": False,
    },
)
```

Evidence Registry:

- rejects duplicate evidence IDs;
- validates execution, tool, asset, and artifact references;
- starts evidence as `unverified`;
- marks `verified` only after successful reference/content validation;
- supports failed status;
- exposes report records for B7 report validation.

Adapters preserve operation parameters, SQL fingerprint, snapshot reference, content hash, and truncation metadata without deleting legacy models.

## Report closure

`AnalysisRuntime.build_verified_report()`:

1. collects verified evidence from the registry;
2. returns no report when there is none;
3. creates deterministic execution-result findings;
4. marks truncated SQLite evidence as a limitation;
5. sets `partial_success` when completed and failed steps both exist;
6. calls `validate_analysis_report()` against Runtime assets, artifacts, and evidence;
7. renders structured Markdown with `render_analysis_report()`;
8. writes the report file and registers a RuntimeArtifact in the agent path.

The report explicitly distinguishes deterministic execution results from LLM business insights.

## RuntimeOutcome

New model:

```python
RuntimeOutcome(
    run_id="run_...",
    status="completed" | "partial_success" | "failed" | "cancelled",
    runtime_mode="runtime_v2" | "legacy_v1",
    report_id="report_..." | None,
    completed_steps=2,
    failed_steps=0,
    evidence_ids=("evid_...",),
    error_code=None,
    fallback_used=False,
)
```

Runtime V2 now sets `session.runtime_outcome` from real task statuses and report closure. This is not inferred from SSE completion.

Example:

```python
RuntimeOutcome(
    run_id="run_123",
    status="partial_success",
    runtime_mode="runtime_v2",
    report_id="report_456",
    completed_steps=1,
    failed_steps=1,
    evidence_ids=("evid_a", "evid_b"),
    error_code=None,
    fallback_used=False,
)
```

## Remaining work

B11.1 does not complete all product integration. Remaining items:

- Multi-step output asset propagation is still limited; B11.2 will address this fully.
- Canonical Evidence Registry is in-memory; persistence can be added in B11.2/B11.3.
- SQLite database asset registration still needs a cleaner semantic model in B11.3.
- API Task Outcome mapping from `RuntimeOutcome` belongs to B11.4.
- Adapter `DataIngestionService` belongs to B11.4.
- API cancellation propagation belongs to B12.
- Docker deployment E2E belongs to B13.
- Default Runtime V2 switch review belongs to B14.

B11.2 can proceed because:

1. Runtime V2 execution now builds and validates a report.
2. Canonical Evidence is registered for deterministic file operations.
3. SQLite evidence is adapted into the canonical registry.
4. RuntimeOutcome reflects real task state.
5. Unsafe plans are rejected before execution.
