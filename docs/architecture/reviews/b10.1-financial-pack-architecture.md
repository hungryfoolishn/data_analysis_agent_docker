## 1. 三层架构归属（复核后确认）

```
Platform（不动）: Runtime V2 Scheduler/Runner/Executor、DataAsset、AssetResolver、
                  OutputBinding、EvidenceRegistry、Verified Report、Session
Acquisition（不动）: Adapter ABC/Registry/Catalog、FetchRequest/FetchResult、
                  AcquisitionService/History、SnapshotStore、AdapterHealthTracker
Financial Pack（新建+改接）: models / periods / catalog / metrics / normalization /
                  adapters 映射 / intent / context / templates / pack contract
```

财务领域规则只允许存在于 Financial Pack。通用 Runtime 不新增任何财务判断。

## 3. Financial Pack Contract（接口草案）

遵循 B9 Macro Pack 已确立的"显式注册、可独立加载、默认不启用"约定：

```python
class FinancialPack:
    def get_domain_name(self) -> str:            # "financial"
    def get_domain_version(self) -> str:         # 语义化版本，随契约演进
    def get_intent_resolver(self) -> FinancialIntentResolver:
    def get_context_builder(self) -> FinancialContextBuilder:
    def get_metric_catalog(self) -> FinancialMetricCatalogView:   # 只读目录视图
    def get_analysis_templates(self) -> Sequence[FinancialTemplate]:
    def validate_request(self, request: FinancialAnalysisRequest) -> list[str]:
        # 返回可澄清问题列表；识别不充分必须要求澄清，不得猜测公司/期间
```

注册与加载（解锁后实施，配套 `tests/test_financial_pack_contract.py`）：

- `register_domain_pack(pack)`：幂等注册；重复注册同名不同版本 → 显式错误。
- 未注册时：通用分析路径与 Macro Pack 行为完全不变（测试断言）。
- 加载失败（模型/目录初始化异常）→ 抛出 `FinancialPackLoadError`，禁止静默降级。
- 与 Macro Pack 并存测试：两个 Pack 同时注册互不可见对方数据、intent 不串扰。

## 4. 输入输出契约

`FinancialAnalysisRequest`（输入，全部可缺省，由 intent/澄清补全）：
entity（company_id | stock_code+market | sec_cik | china_stock_code）、market
(us | cn)、statement_type（income|balance|cash|all）、periods（FY/Q1..Q4/H1/9M/
YTD/TTM + 期望 basis）、metrics（metric_id 或意图推导）、analysis_goal、
comparison（单实体多期 / 同市场对比 / 中美对比）、source_constraints
（仅 SEC / 仅巨潮 / fixture）、reporting_basis、currency 偏好。

`FinancialAnalysisPlan`（输出）：
- required_datasets：dataset_id + FetchRequest 参数（走 B8）；
- required_assets：期望的 DataAsset 语义键（§6）；
- metric_jobs：metric_id + inputs + period 语义 + basis + version；
- template_id + steps（映射为 Runtime V2 `AnalysisPlan` steps，method 仍为
  `run_analysis_operation` 等通用 allowlist 工具 + 财务模板步骤参数）；
- evidence_requirements、risk_rules、limitations。

显式不做：把财务步骤塞进通用 Planner；Financial Pack 输出的 RuntimePlan 仅
由既有通用 method 组成，财务语义存在于步骤参数与 Pack 内计算资产中。

## 5. 与 B8 的接入契约（B10.5）

- 新增 B8 数据集（稳定、可区分市场）：
  - `sec_company_facts`（参数：cik/ticker、concept 集或全量、单位、期间、
    form 10-K/10-Q）— 处理 units/frame/fy/fp/accession/重述维度；
  - `cn_company_filings`（参数：stock_code、报告类型 年报/一季报/半年报/三季报、
    报告期间）— 来源以实际可用、合法访问的官方渠道为准（巨潮/交易所），
    接口不可用时的降级与失败分类必须显式；
  - 两者均要求：原始 filing URL、accession/公告 ID、filing date、报告期间、
    原始科目与单位；HTTP 200 ≠ 有效财报数据（内容校验 + 质量规则）。
- 数据流：`Adapter → FetchResult → AcquisitionService → SnapshotStore →
  DataAsset`（原始层），Pack 经 `AssetResolver` 读取原始快照做标准化 →
  标准化结果注册回 Runtime（`register_fetch_result` 等价路径或
  `register_dataframe` + provenance），保持单一资产/快照体系，无平行存储。
- 真实 API Smoke 单独标记，凭据/网络缺失时 skip，不计入通过。

## 6. 资产身份 Key（与 B9 对齐，不另造体系）

财务标准化结果在 Runtime 中注册为 DataAsset 时，其 provenance 身份键为：

```
market + entity_id + canonical_concept + statement_type
+ period(period_type, fiscal_year[, quarter]) + reporting_basis
+ currency + version(filing/accession)
```

与 B9 `IndicatorAssetKey`（Option C，c310cb0 进行中）保持同一组合键哲学：
概念不作为唯一键，主体+概念+期间+口径组合唯一。B9 冻结后若其最终键结构
与本节不一致，以 B9 为准修订本节并同步测试。
