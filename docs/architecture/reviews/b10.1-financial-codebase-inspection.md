### 1.3 与 Platform / B8 / B11.2 的真实关系（关键结论）

- `git grep` 验证：`runtime/financial` 与 `runtime/financial_agent` **没有任何
  模块导入** `AcquisitionService / AdapterRegistry / SnapshotStore /
  DataAsset / EvidenceRegistry`。财务数据路径完全绕过 B8（CSV/manifest 文件直读），
  证据与验证使用域内自建模型，未进入 Platform 的 EvidenceRegistry /
  Verified Report。
- 这与 B10 目标架构的根本差距：**B10 不是"新建 Pack"，而是把一个自洽的
  V9/V10 财务子系统改接（re-plumb）到 Platform + B8 + B11.2 上**，同时保留
  其可复用的领域模型/指标/期间/单位逻辑。

### 1.4 数据接入现状

- `scripts/fetch_financial_real_data.py` / `generate_financial_golden.py` /
  `generate_real_financial_golden.py`：脚本化真实数据落地为 fixtures（
  `tests/financial/data`、`real_data`、`formula_golden`、`golden_cases`）。
- 无 SEC XBRL / 巨潮披露的 B8 Adapter；B8 现有 `sec_company_revenues /
  sec_company_net_income`（companyconcept，单概念）远不足以支撑三大报表。
- 结论（B10.5 方向）：财务 Adapter 应按 B8 `HttpJsonAdapter` 契约新增
  `sec_company_facts`（多概念/单位/frame/accession 维度）与中国披露渠道
  数据集；`FetchResult` 原始数据进 SnapshotStore/DataAsset，财务标准化在
  Pack 内消费 DataAsset（经 AssetResolver），保证 B8 血缘不被绕过。

### 1.5 通用 Runtime / Prompts / Webui

## 2. 审计结论（处理方式汇总）

1. **复用（不改语义）**：metrics 注册表架构、period 解析/比较框架、unit
   normalizer、finding/risk/anomaly 引擎、workflow 域内编排、formula golden
   底座、V10 计划校验。
2. **扩展**：period（TTM/累计转单季/期间边界/非自然财年）、unit（数值单位
   与货币分离、汇率通道）、metrics（B10.4 定义结构+口径配置+校验规则）。
3. **重构**：models（float→Decimal、固定字段→canonical line item、补充
   period_start/end、filing/accession/source 元数据、Entity Identity）。
4. **改接（re-plumb）**：数据路径接 B8（Adapter→FetchResult→AcquisitionService
   →SnapshotStore→DataAsset→AssetResolver→Pack 标准化）；执行入口接 Runtime
   V2（淘汰自建 scheduler/executor 作为生产路径）；Evidence/Report 接
   Platform EvidenceRegistry / Verified Report（域内 evidence 保留为计算明细）。
5. **禁止**：把财务规则写入通用 Runtime；删除或弱化 V9/V10 既有测试；为
   形式新建平行资产/证据/调度体系。
