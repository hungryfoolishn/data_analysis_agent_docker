## 3. IndicatorAssetKey 最终契约

`langgraph_langchain/runtime/macro/registry.py`：

- 契约：frozen dataclass，6 字段 `indicator_id / country / concept / frequency / source_id / dataset_id`。
- 身份分层：资产身份（6 字段）；查询条件（期间范围等）**不进入** Key；数据属性（unit / seasonal_adjustment / price_basis / base_period）由 `MacroIndicator`/`MacroTimeSemantics` 承载，比较前经 `comparable_with` 校验；资产版本由 `RegisteredIndicatorAsset.data_version` 承载。
- 唯一解析入口：`resolve_indicator_asset_key(indicator: MacroIndicator)`（B9.8.2 §3.2）。所有模块（Intent、Template Requirement Resolver、Plan Builder、Data Sufficiency、比较管线）统一经由该入口；禁止各模块自行拼装 Key。
- 便利查询保留多结果语义：`resolve_by_concept()` 返回列表；`resolve_unique_by_concept()` 歧义时抛 `ValueError`。`observations` 字典以 `indicator_id`（目录内唯一稳定）为内部索引。
- 足以区分：US GDP vs CN GDP、同 concept 不同频率/来源/口径（阶段 1 测试 `tests/test_macro_requirement_resolution.py` + `tests/test_indicator_asset_registry.py` 全部覆盖）。

## 5. 跨国家比较执行流程

新模块 `langgraph_langchain/runtime/macro/comparison.py`：

```
ComparisonSpec(countries, concepts, comparison_method=yoy_rate, alignment_policy=common_period)
  → CrossCountryComparator.resolve(spec)
      per-(concept, country) 资产腿（CountryAssetLeg，独立 IndicatorAssetKey）
      → 语义可比性判定（rate_nature：rate/real/nominal；real vs nominal 直接比较 → 阻断并披露原因）
      → 指标统一（published YoY 原样透传不重差分；level/index 做 PeriodIndex 感知 yoy；annual yoy=上年差）
      → 频率归一（取最粗公共频率，子年度→年度按日历期间均值，显式披露）
      → 真实期间对齐（PeriodIndex inner join；重复期间按均值合并并披露；<2 个共同期间 → 阻断披露）
  → build_aligned_frame() → MacroRuntimeIntegration.build_aligned_asset()
      经 register_dataframe 快照化注册（含输入资产/数据版本/披露血缘）→ 进入生产执行计划
```

模板选择（`_select_template`）不再只看 concept 数量：显式比较意图（对比/比较/compare）＋ ≥2 国家 → 新模板 `cross_country_comparison`；仅提及两国无比较词 → 仍走联合分析；多 concept 且被单一模板（required∩非空且 ⊆ required∪optional）覆盖 → 优先专属模板（CPI+PPI→inflation 等）。

## 7. 数据对齐策略（§4.5 全规则落地）

1. 禁止按行号拼接：全部基于 `pd.PeriodIndex` 真实期间键 inner join。
2. 频率不同：归一到最粗公共频率（月/季→年度均值），显式披露，不静默重采样、不把月度当季度。
3. 缺失期间：inner join 收缩共同期间集，覆盖范围披露；共同期间 <2 → 阻断披露。
4. 重复期间：期间解析层按均值合并并披露；transform 层（`transforms._prepared`）对重复期间快速失败（防线）。
5. CPI 基期不同：不比较指数绝对值，统一到同比速率比较；published YoY 不重差分（B9 §5.5）。
6. GDP 名义/实际：速率性质（real vs nominal）不一致 → 阻断直接比较并披露原因。
7. 变换引擎修复（通用层）：annual yoy 支持（lag=1）；Period dtype 输入直接接受（pandas 4 兼容）；BLS `YYYY-MNN` 期间显式解析。

## 8. Evidence 生产链路

真实链路（`tests/integration/macro/test_evidence_production.py` + harness）：

```
真实 run_analysis_operation 工具
  → SessionExecutionRecorder（canonical execution_id，由 StructuredTaskExecutor 注入）
  → register_dataframe(execution_id 元数据) → collect_operation_evidence
  → canonical_from_operation_evidence(task_id=session.current_runtime_step_id)
  → runtime.register_canonical_evidence（引用强校验）
  → on_task_finish → record_execution_result
  → _adjudicate_output_bindings（expected_outputs/output_name 校验，all-or-nothing）
  → _verify_canonical_evidence_for_execution（内容验证 → verified）
  → EvidenceRegistry → build_verified_report（仅 verified 证据入报告）
```

- Retry 语义：`AnalysisRuntime(force_new_run=True, parent_run_id=…, retry_of_step_id=…)` → attempt+1、全新 canonical execution 身份、binding 归属当前 attempt（E2E 验证）。
- 真实关联样例（G15 一次生产执行）：`run_id=run_f0818bb6…`，`attempt=1`，binding `(step_11a3f31c…, output_name, attempt=1, exec_718ccf32…)`，evidence `evid_6768cf9f…`（task=step_11a3f31c…，execution=exec_718ccf32…，input=[asset_4e959a31…]，output=[asset_2591624f…]），`report_id=report_a7d08357…`（4 findings / 7 引用资产）。
- 拒绝行为验证（§5.4-9/10/11）：伪造 task_id / 未知 execution 的证据注册被 `EvidenceRegistryError` 拒绝；引用不存在逻辑输出的计划被 Runtime 计划校验拒绝；无 verified 证据时 `build_verified_report` 返回 None；报告引用未知证据 → 校验不通过。

**过程中发现并修复的两个通用 Runtime 缺陷（在通用边界修复，未写入 Macro 专属逻辑）**：

1. `context.py` 状态恢复与 `_create_retry_run` 对 `self.artifacts` 整体替换（assets 早已原位更新，artifacts 没有）→ EvidenceRegistry 持有陈旧字典引用，恢复/重试 run 上注册的工件对证据校验不可见。修复为原位更新；新增通用回归 `tests/test_runtime_state_restore_evidence_views.py`；B11.2 回归通过。
2. `structured_executor.py` 不识别 `tool_error` 契约（`{"error": …}` JSON），工具失败被判成功，下游 binding 解析失败。修复为识别顶层 `{"error": …}` → failed（ToolExecutionError）。
