## 5. 本轮修复的部署问题（真实缺陷，已验证）

### D1: docker-entrypoint.sh 缺少执行权限（P0 部署缺陷）

- 证据: 首次启动容器 `Exited (126): exec /app/docker-entrypoint.sh failed: Permission denied`
- 根因: git 索引中文件 mode 为 100644（无 +x 位）
- 修复: `git update-index --chmod=+x docker-entrypoint.sh`（mode→100755）+ Dockerfile 增加 `RUN chmod +x /app/docker-entrypoint.sh` 防御
- 验证: 修复后容器正常启动，gosu 降权生效（app 进程 uid=telebi）

### D2: 基础镜像残留旧 /app 文件（P1 部署正确性缺陷）

- 证据: 容器 `/app/tests/conftest.py`（md5 fa280b12，日期 2025-08-23，CRLF）存在于镜像但不在 a17b9ff 源码树中；与生产 deepanalyze 镜像内同名文件完全一致
- 根因: 基础镜像 `telebi-telebi-base:latest` 内嵌旧版项目快照；`COPY . /app/` 只叠加不删除，旧文件残留
- 污染文件清单（tests 域）: `tests/conftest.py`、`tests/run_tests.py`、`tests/test_config.py`
- 影响: 残留 conftest.py 引用不存在的 pytest 插件导致测试无法运行；生产镜像（deepanalyze）存在同样问题
- 修复: Dockerfile 在 `COPY . /app/` 前增加 `RUN rm -rf /app && mkdir -p /app`
- 验证: 重建后 3 个残留文件全部消失；全量测试可正常运行

**注意: 生产 deepanalyze 镜像同样受 D2 影响，建议后续重建生产镜像时采用相同修复。**
