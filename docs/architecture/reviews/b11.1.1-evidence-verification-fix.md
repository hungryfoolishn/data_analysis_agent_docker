# B11.1.1 Canonical Evidence Verification Fix

Status: complete
Baseline: `9c18eb49d47d475d36a7a474a98c6f7af4f60448`
Scope: evidence verification semantics and RuntimeOutcome status mapping.
B11.2 was not started.

## Original issues

1. **Fabricated execution IDs could pass.**
   `EvidenceRegistry` only checked that `execution_id` was non-empty. It did not
   verify that the ID corresponded to a real Runtime execution.

2. **`verified` meant only "references valid".**
   `EvidenceRegistry.verify()` had no required content validator. With only valid
   asset/artifact IDs, evidence was marked `verified` even though content and
   output were not checked.

3. **Legacy verified status could leak into canonical evidence.**
   `canonical_from_legacy_evidence_item()` inherited `verified` from the legacy
   model instead of starting canonical evidence as unverified.

4. **Skipped/cancelled tasks were not consistently mapped.**
   RuntimeOutcome could treat succeeded + skipped as fully completed, and report
   status only considered failed steps.

## Fix

### Evidence status lifecycle

`CanonicalEvidence.validation_status` now has an explicit progression:

```text
unverified
  -> reference_validated
  -> verified
```

Failure can transition from any pre-verified state to `failed`.

`EvidenceRegistry.register()` always resets evidence to `reference_validated`
after reference checks. It never preserves a caller-supplied `verified` status.

### Execution reference validation

`EvidenceRegistry` accepts an execution lookup provider:

```python
EvidenceRegistry(
    assets=...,
    artifacts=...,
    executions=execution_lookup,
)
```

`AnalysisRuntime` passes a lookup against `runtime.executions`. A fabricated
execution ID now fails with `Unknown execution_id`.

### Required content validation

`EvidenceRegistry.verify()` requires a content validator. Without one, evidence
is marked `failed` and raises:

```text
Evidence content validator is required before verification
```

`AnalysisRuntime._validate_canonical_evidence_content()` checks:

- output assets exist;
- referenced artifacts exist;
- artifact files exist;
- operation `row_count` matches output asset row count;
- SQLite `returned_row_count` matches snapshot reference row count.

### Deferred verification

Tools register canonical evidence after the real execution is recorded, so the
evidence starts as `reference_validated`. Runtime V2 then verifies content after
`record_execution_result()` adopts the real execution.

### RuntimeOutcome mapping

`derive_runtime_status()` in `runtime/outcome.py` now maps:

| Task state combination | RuntimeOutcome |
| --- | --- |
| any cancelled | cancelled |
| succeeded + failed | partial_success |
| failed only | failed |
| succeeded + skipped | partial_success |
| succeeded only | completed |
| skipped only | failed |
| no terminal tasks | failed |

`build_verified_report()` also treats skipped steps as partial completion and no
longer reports skipped work as full success.
