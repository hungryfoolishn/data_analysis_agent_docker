## 4. Root Cause Analysis

The remaining failures stem from a **design tension** between two B9.8 requirements:
1. Use `indicator_id` (not `concept`) as asset key to avoid multi-country collision
2. Templates check sufficiency by `concept` (existing contract)

Resolving this requires either:
- A: Change templates to check by indicator_id (breaks concept-based template definitions)
- B: Keep concept key but use composite `concept_country` (breaks single-country lookups)
- C: Introduce an `IndicatorAssetKey` model as recommended but not yet implemented

**Recommendation**: Option C is the correct long-term fix, requiring:
1. `IndicatorAssetKey` dataclass
2. Template sufficiency updated to use key-based resolution
3. Plan builder updated to reference by key
4. ~2-3 additional implementation sessions

## 5. Recommendation

B9.8 should be treated as **partially complete** with the following next steps:
1. Implement `IndicatorAssetKey` resolution (fixes multi-country collision)
2. Update template sufficiency to use key-based checking
3. Add E2E tests per B9.8.8 scenarios A-H
