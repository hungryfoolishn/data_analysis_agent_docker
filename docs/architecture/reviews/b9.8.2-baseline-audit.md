## 3. IndicatorAssetKey 当前定义

`langgraph_langchain/runtime/macro/registry.py:17-51`，frozen dataclass，6 字段：

| 字段 | 语义 |
|---|---|
| `indicator_id` | 目录内唯一指标 ID（如 `us_gdp_real_quarterly`） |
| `country` | `us` / `cn` |
| `concept` | 业务概念（`gdp`/`cpi`/…） |
| `frequency` | `monthly`/`quarterly`/`annual`/… |
| `source_id` | AdapterRegistry adapter_id |
| `dataset_id` | DatasetCatalog dataset_id |

- 资产身份（identity）与数据属性（unit/price_basis/seasonal_adjustment/base_period，在 `MacroIndicator`）已分离；查询期间不进入 Key（正确）。
- 足以区分：US GDP vs CN GDP、同 concept 不同频率、不同来源。
- 局限：同 concept 同国家同 dataset 的不同统计口径（如 unit 差异）依赖目录校验 `(concept, dataset_id)` 唯一（`models.py:68-82`）保证不重复；Key 本身不含 unit/price_basis，但目录模型约束下这 6 字段在当前目录内已可唯一定位。本轮不机械加字段，维持 6 字段契约。

## 4. Registry 当前索引结构

`IndicatorAssetRegistry`（registry.py:65-157）：

- 主索引 `dict[IndicatorAssetKey, RegisteredIndicatorAsset]`，per-run 生命周期。
- `register()`：同 Key 同 asset_id 幂等；同 Key 不同 asset_id 抛 `ValueError`（防覆盖）。
- 便利查询：`resolve_by_indicator_id()`（首个匹配）、`resolve_by_concept()`（过滤列表）、`resolve_unique_by_concept()`（歧义抛 `ValueError`）。

## 5. Intent 当前资产身份结构

`MacroIntentResolver.resolve()`（intent.py:89-117）产出 `MacroIntent{question, concepts, countries, years, analysis_goal, ambiguities}`——仅 concept/country 字符串列表，**不含 IndicatorAssetKey**。Key 的构造只发生在 `MacroRuntimeIntegration.run()` 内部（intent.py:250 `IndicatorAssetKey.from_indicator(indicator)`）。

## 6. Template 当前资产匹配规则

- 模板以 `required_concepts` / `optional_concepts` / `any_of_concepts` 表达需求（templates.py:39-156）。
- `check_data_sufficiency()`（templates.py:178-209）：从 resolved 指标对象提取 concept 集合做匹配；any_of 组间 OR（任一组全满足即可）；`min_observations` 不足降级 partially_ready。
- `build_template_plan()`（templates.py:212-363）：`used` 过滤后在 templates.py:253 用 **concept 字符串** `used.get(primary_concept)` 查找以 indicator_id 为键的 dict——永远 miss，靠 `next(iter(used.values()))` 兜底，"primary 资产"实际取插入顺序首个（隐性缺陷 D7）。

## 7. Data Sufficiency 当前匹配规则

同上（`check_data_sufficiency`）。要求语义现状：
- `required_concepts`：全部满足 ✓
- `optional_concepts`：不阻断 ✓
- `any_of_concepts`：组内 AND、组间 OR ✓（B9.8.4 已修）
- `countries`：**完全不参与**——`required_concepts=["gdp"]` 由任一国家的 gdp 资产即满足，跨国家请求不检查"每国均需数据"。
- `frequency/unit/price_basis`：不参与 sufficiency；`MacroTimeSemantics.comparable_with()`（models.py:158-186）存在但**无任何调用方**。

## 8. `build_aligned_asset()` 当前状态

`intent.py:168-214`。**定义了但从未被 `run()` 调用**——生产链路断开（方案 §4.4 指认属实）。且实现本身有缺陷：

1. 列名直接用 `entry.key.concept`：US GDP 与 CN GDP 都映射到列 `"gdp"`，`frames` dict **互相覆盖**，对齐后只剩一个国家的数据。
2. 对齐方式为原始 period 字符串 inner-join：FRED 季度 period（`2025-01-01` 样式）与 NBS 年度（`2024`）完全不相交 → 空对齐结果，无频率/期间归一化。
3. 无 unit/price_basis/base_period 可比性校验（未用 `MacroTimeSemantics.comparable_with`）。
4. `frames` 只保留每资产最后写入的 series，多处 `set_index("period")` 假设列名存在，无重复期间去重。

## 10. Evidence 关联字段

`CanonicalEvidence`（evidence/models.py）：`evidence_id / execution_id / task_id / tool_name / input_asset_ids / output_asset_ids / artifact_ids / numeric_values / validation_status`。attempt 身份由 `execution_id`（`new_id("exec")`）承载，retry 生成新 execution。EvidenceRegistry.register 强校验：execution 存在、task_id/tool_name 与 execution 一致、execution status=succeeded、资产/工件 ID 均已注册。
