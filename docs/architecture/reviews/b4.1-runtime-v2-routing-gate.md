### 1.2 路由决策语义（runtime/runtime_route.py）

- `RuntimeSelectionPolicy.from_env()`：`RUNTIME_V2_ENABLED` 默认 **False**（`runtime_route.py:38`；`config.py:86` 一致）→ `decide_runtime_route` 返回 `legacy_v1`（reason=`runtime_v2_disabled`，:65-67）。
- V2 开启时返回 `runtime_v2`（reason=`runtime_v2_completed`）；V2 运行中 infra 失败时按 `fallback_enabled`（默认 False）与 `strict_mode`（默认 True）决定是否回退 Legacy。
- **运行中二次决策**：`run_analysis_stream` 内 V2 返回 failed/blocked/incomplete/limit_reached 时（:1668-1690）再次调用 `decide_runtime_route`，写入 `session.runtime_route_decision` / `runtime_v2_fallback`：
  - 业务失败（result 非空，如 `failed`）→ **不回退 Legacy**，生成 `build_verified_report()` + `build_runtime_outcome(runtime_mode="runtime_v2", fallback_used=...)` 后终止；
  - 基础设施失败（result 为空的 blocked/incomplete/limit_reached）→ 仅当 policy 允许时回退 Legacy。
- V2 完成后：报告写盘 `final_report.md` + `final_report.md` 工件注册（:1958-1975），`_set_runtime_run_status("completed")`。

### 1.3 多入口一致性回答（任务 §4.A）

1. **入口**：进程内唯一分析入口是 `run_analysis_stream`；WebUI 是 API 的 HTTP 客户端；`tests/runtime_v2/*` 直接构造 `AnalysisRuntime`/`RuntimeV2Controller` 属测试专用入口，绕过路由（见 §1.5）。
2. **决策层**：`run_analysis_stream` 内 `decide_runtime_route(policy)`（langgraph_agent.py:1841）；无其他决策点。
3. **开关生效层**：环境变量 `RUNTIME_V2_ENABLED/FALLBACK/STRICT_MODE` → `RuntimeSelectionPolicy.from_env` → `decide_runtime_route`；`config.py:86-96` 提供同语义配置常量（Legacy 会话模块消费）。
4. **语义一致性**：单一决策点 + 单一 policy 来源，未发现开关语义分叉；但 SQLite 会话的计划准备（:849）是无条件的，路由仍按统一开关——即默认配置下 SQLite 会话的 V2 计划已就绪却仍执行 Legacy ReAct（见 §3 缺口）。
5. **测试专用入口**：`tests/runtime_v2/`、`tests/test_b11_1_runtime_closure.py` 等直接驱动 `AnalysisRuntime.execute_next_task` / `RuntimeV2Controller`；`tests/test_run_history.py:325` monkeypatch `api_server._run_analysis_stream`（路由层仅 mock）。生产入口只有一条，无绕过。

## 2. Legacy / Runtime V2 路由对比

| 维度 | Legacy ReAct | Runtime V2 |
| --- | --- | --- |
| 触发 | `RUNTIME_V2_ENABLED` 缺省（默认路径） | 显式 `RUNTIME_V2_ENABLED=1` |
| 执行体 | `create_react_agent` + `astream_events`，LLM 驱动工具调用 | `initialize_plan` → Scheduler → TaskRunner → StructuredTaskExecutor |
| 输入 | `session.ns["df"]` / 工具内注册（`load_data` 等） | `AssetResolver.resolve_many` → `namespace.runtime_inputs` + Binding 逻辑引用解析 |
| 输出 | 工具自由产物 + LLM 报告 | `ExecutionResult.output_assets` + OutputAssetBinding（单点写入） |
| 证据/报告 | `tool_record_finding`/`tool_finish_report` 由 LLM 驱动 | `build_verified_report()`（验证 evidence 后构建，报告校验） |
| 失败语义 | 阶段状态机 + recovery | Scheduler skip 级联 + `build_runtime_outcome` + 显式 no-fallback 终止 |
| 会话数据 | `SessionPersistence`/`restore_state` | 同一会话机制（`run_analysis_stream` 入参 `restore_state` 共用） |

## 4. Runtime V2 输出链路核查（任务 §4.C）

以 `tests/runtime_v2/test_runtime_e2e.py::test_runtime_v2_grouped_sales_e2e` 为基准（真实 Runtime V2 Scheduler 链路）：

- **真实 Scheduler**：`initialize_plan → TaskScheduler → RuntimeV2Controller.graph → execute_next_task`（断言 10 步 DAG 顺序执行、run/steps 全部 succeeded）。
- **Execution ID 贯穿**：B11.2.1 后 canonical id 从 request → 工具注入 → Recorder → 资产 metadata → ExecutionResult → Binding → Evidence（`tests/test_output_binding_execution_id.py` 断言全链）。
- **输出绑定**：`record_execution_result()` 单点校验+注册（`tests/test_output_binding_named_outputs.py` 等 78 用例）。
- **Evidence 引用**：e2e 断言每个 finding 的 evidence 与 execution/artifact 关联且 verification 全部 passed。
- **失败向上传播**：runner 失败 → skip 级联 → run failed（`test_runtime_runner_commit4.py`、`test_output_binding_skip.py`）；业务失败不回退 Legacy（`run_analysis_stream:1668` 分支 + 无静默回退断言）。
- **Report 消费真实执行结果**：`build_verified_report()` 仅消费 verified evidence（`context.py`）；e2e 断言报告通过 `validate_analysis_report`。
- **结论**：Runtime V2 文件链路的执行→绑定→证据→报告在测试意义上已是端到端；缺口在"覆盖面"（Excel/Parquet/多轮）而非"链路存在性"（与 B0 结论一致）。

## 6. 已有能力与真实缺口

**已具备**：单一入口 + 单一决策点的路由机制；V2 全链路执行/绑定/证据/报告闭环（测试级）；SQLite V2 计划无条件就绪；失败不静默回退；会话持久化与计划控制。

**真实缺口（B4 范围内）**：
1. 默认路由仍为 Legacy（`RUNTIME_V2_ENABLED` 默认 False，config.py:86）。
2. Excel / Parquet 无 V2 e2e；Parquet 连读取单测都缺。
3. 多轮追问 / Session 续跑未穿过真实路由验证。
4. 通用 Planner 只有确定性窄集（`PLAN_OPERATIONS`），覆盖不了 toDo.md Phase 1A 的自然语言场景（B4.2 主题）。
5. SQLite 会话在默认配置下"V2 计划就绪但执行 Legacy"的路由不对称（B4.2/B4.3 需给出显式处理：要么 sqlite 会话强制 V2，要么文档化该不对称）。

## 8. B4.2 Planner 扩展建议

1. **边界**：保留 `DeterministicAnalysisPlanner` 作为兜底与测试基准；扩展目标是"自然语言 → 经校验的 AnalysisPlan"。
2. **分层设计**：LLM 规划器产出结构化 `GeneralPlanStep`（operation 必须命中 `PLAN_OPERATIONS` 白名单）→ 现有 `validate_runtime_plan` 全量校验 → 校验失败回退确定性 Planner 或澄清提问，绝不跳过校验直连执行。
3. **Schema 注入**：将 `register_file_asset` 已有的 `scan_schema().schema_snapshot.columns` + 数据质量摘要（eda 结果）注入规划上下文，满足 toDo.md "Planner 真正基于 Schema/数据摘要生成计划"。
4. **范围冻结**：B4.2 只覆盖 toDo.md Phase 1A 首批分析方法（描述统计/分组比较/趋势/异常/相关/TopN/比率/质量），不引入 SQLite SQL 规划（B5）与领域语义（B9/B10）。
5. **验收挂钩**：每个新场景必须落入 G1–G10 门禁对应的 e2e，而非新增孤立单测。

## 9. B4.3 文件 E2E 补齐建议

1. `test_runtime_v2_excel_e2e`：Excel（含多 sheet 选择）→ 同 e2e 10 步模式；覆盖 G2/G5/G7。
