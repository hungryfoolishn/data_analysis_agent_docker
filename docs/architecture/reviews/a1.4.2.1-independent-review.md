## 2. Gate-by-gate findings

### Gate A — Contract
- `WorkerJob` is JSON-safe; artifact path validation rejects absolute paths, `..`,
  and empty segments. Timeout clamped (default 60s, max 3600s).
- `ProcessWorkerJob.namespace` is `dict[str, Any]` — a deliberate process-only
  compatibility field required by fork-based execution. Risk is documentation and
  future misuse, not current behavior; the Docker stub rejects process-only data.

### Gate B — Backend
- `ProcessWorkerBackend` wraps the existing `IsolatedPythonExecutor` (no reimplementation).
- Capabilities honestly advertise: cancellation/timeout true; network / filesystem /
  resource / container isolation all false.
- `DockerWorkerBackend` is fail-closed: no container creation, no socket access,
  `UnsupportedBackendError` on execute/cancel, `not_implemented` health.

### Gate C — Dispatcher
- Default backend `process`; no implicit fallback; invalid selection raises;
  Docker selection maps to FAILED + `BACKEND_UNSUPPORTED`.
- Duplicate active job id rejected; cancel idempotent; pre-dispatch cancel → CANCELLED;
  post-completion cancel does not rewrite succeeded → cancelled (A1.3 race contract).
- Backend `job_id` mismatch → FAILED + INTERNAL.

### Gate D — Cancellation / Timeout
- Verified by `tests/runtime_v2/test_runtime_v2_cancellation.py`,
  `test_isolated_python_executor.py`, and the dispatcher suite.

### Gate E — Runtime Compatibility
- V1 `_Session.run_code` dispatches through the process backend and preserves
  timeout/cancelled/failed semantics (verified by `langgraph_langchain/test_reliability.py`
  and parity tests).
- V2 `PythonTaskExecutor` routes through the dispatcher; SSE streaming and e2e suites pass.
- `RUNTIME_V2_ENABLED` default unchanged.

### Gate F — Security Boundary
- No Docker production path introduced; no Docker socket access; no default routing change.
- The process backend remains non-sandboxed; this is explicitly documented rather than hidden.

### Gate G — Git
- Commits are individually scoped (docs → contract → backend → dispatcher → runtime → fix).
- Final `git status --short` clean before each commit; no `git add .`; no destructive operations.
