## 3. Financial Asset Identity 设计（冻结）

Financial Pack **不使用** Macro 的 `IndicatorAssetKey`（B10.1 §1.1 隔离契约）；在 financial 域内定义自己的键，遵循同一组合键哲学（概念不作唯一键），并显式分四层：

### 3.1 逻辑资产身份 `FinancialStatementKey`（进入键，9 维）

```text
market             us | cn（扩展市场为显式枚举/白名单）
entity_id          Financial Pack 内部稳定 ID（不得依赖 ticker 单独成立）
canonical_concept  规范科目概念（line-item 映射后的 canonical 概念）
statement_type     income | balance | cash
period_type        instant | duration
fiscal_year        int
fiscal_period      FY | Q1..Q4 | H1 | 9M | YTD | TTM
reporting_basis    consolidated | parent（合并/母公司，显式区分）
currency           ISO 4217（CNY/USD/…，显式、默认不猜测）
```

### 3.2 版本层（不进入逻辑键，分层记录）

| 层 | 载体 | 规则 |
|---|---|---|
| 原始来源身份 | `accession_number`（SEC）/ 公告 ID（CN）+ `source_document_id` | 同 B9 的 source_id/dataset_id 角色：来源不同 → 不同注册条目 |
| 申报修订 | `amendment` 标志 + accession 序列 | 同期间不同 accession = 重述，**新版本不覆盖旧版本** |
| 数据内容版本 | `DataAsset.content_hash`（Platform 承载） | 同 accession 内容变化 = 数据修订，content_hash 变化 → 新 DataAsset |
| 标准化转换版本 | `FINANCIAL_NORMALIZATION_VERSION`（financial 域内独立版本，不使用 B9 的 `STATISTICS_VERSION`） | 转换规则演进不改变数据内容版本 |

### 3.3 §5.3 八问逐一回答

1. **同一 Entity 不同报表区分身份？** 是——`statement_type` 在键内（income/balance/cash 互为不同资产）。
2. **同一期间不同 accession 区分版本？** 是——进入来源身份层：新 accession = 重述版本，注册为**新的并行版本条目**（保留旧版本可追溯），不覆盖。
3. **同一 accession 内的修订数据？** `amendment` 标志 + `content_hash` 变化识别；注册规则同 B9：同键同 accession 同内容幂等，同键同 accession 不同内容 → 显式冲突（携带修订披露），不静默覆盖。
4. **同一概念不同币种？** 不同标准化资产——`currency` 在逻辑键内；跨币种比较必须经显式汇率通道（B10.2 不实现 FX，缺汇率即不可比，记录原因）。
5. **同一企业不同市场？** `market` 在键内 + `entity_id` 生成规则强制含市场限定（同 ticker 不同市场 = 不同 entity）。
6. **合并 vs 母公司报表？** `reporting_basis` 在键内（consolidated / parent 显式枚举，缺失即拒绝注册，不得默认合并）。
7. **标准化结果如何追溯原始 filing？** 注册 DataAsset 时 `source_metadata` 记录：原始 `dataset_id`（B8 层）、accession/公告 ID、filing_date、原始科目名（`original_concept`）、`FinancialStatementKey` 各维度、`conversion_methods`、`normalization_version`——Evidence（B10.6）据此关联源资产。
8. **`data_version` 与 filing/accession 的关系？** 分层：accession = 逻辑来源身份（重述粒度）；`DataAsset.content_hash` = 内容版本（B8 既有机制承载）；二者独立演进——同一 accession 内容不变时 content_hash 稳定，重述时 accession 变化产生新版本条目。

### 3.4 与 Platform DataAsset 的映射

- 标准化结果经 `AnalysisRuntime.register_dataframe(dataframe=…, source_path=…, source_type=…, source_metadata={…})` 快照化注册（B9.8.2 已验证的正当路径），**无平行资产存储**；
- `FinancialStatementKey` 各维度 + 版本层字段全部进入 `source_metadata`（平台对 metadata 是透明存储）；AssetResolver 按 `asset_id` 消费，键用于 provenance 与注册冲突判定；
- 原始层：B10.5 Adapter → `FetchResult → AcquisitionService → SnapshotStore → DataAsset`；Pack 经 AssetResolver 读原始快照，标准化后注册为新资产（B10.1 §5 契约，B10.2 只建模型与映射规则，不建 Adapter）。

### 3.5 注册规则（B10.2.2 实现 `FinancialStatementRegistry` 时冻结）

同 B9 `IndicatorAssetRegistry` 行为：同 key 同 accession 同 content_hash 幂等；同 key 同 accession 不同 content_hash → `ValueError`（冲突披露）；同 key 不同 accession → 并行版本条目（最新 + 历史可查）；registry per-run 生命周期，不跨 run 共享。

## 4. 与 B10.1 契约的一致性核对

- B10.1 §6 草案键为 `market + entity_id + canonical_concept + statement_type + period + reporting_basis + currency + version(filing/accession)`；本文档将 `period` 细化为 `period_type + fiscal_year + fiscal_period`（instant/duration 不可简化为单一年份字段），并将 `version(filing/accession)` 从逻辑键移入来源身份层（与 B9"来源在键内、内容版本在条目上"的实现对齐）。属细化而非冲突，已按"以 B9 实际实现为准"原则修订。
- 未发现与 B10.1 其他契约（§3 Pack Contract、§5 B8 接入）冲突。

## 5. 风险与未决问题

- `entity_id` 的生成规则（市场限定 + 权威标识来源）在 B10.2.2 Entity 建模中固化；不凭空创建外部企业标识（无权威源时 entity_id 为内部 ID，外部标识进 `identifiers` 映射并记录来源与有效期）。
- CN 披露渠道无统一 accession 语义（公告 ID 粒度不一）：B10.5 Adapter 设计时定义 `source_document_id` 规范，本阶段仅保留字段位。
- 非自然财年（fiscal_year ≠ 自然年）的 period_start/end 精确边界依赖 B10.3 periods 扩展；本阶段键中 fiscal_year/fiscal_period 为显式声明值，不推导。
