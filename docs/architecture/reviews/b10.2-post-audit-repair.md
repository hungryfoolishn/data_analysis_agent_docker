## 1. Repair Summary

The independent audit invalidated the original B10.2 freeze. Four P1 defects were closed and seven P2 risks were assessed. Seven P2s were repaired in this pass because they directly affected period, identity, currency, or traceability semantics; no data-loss issue was deferred.

| Issue | Result | Evidence |
|---|---|---|
| P1-1 invalid statement dates | Closed | strict ISO YYYY-MM-DD, calendar validation, start/end order |
| P1-2 lossy canonical-to-legacy conversion | Closed | reject `source_document_id`, unknown extra concepts, wrong statistic kind/currency/denominator |
| P1-3 untraceable registry facts | Closed | require valid `FinancialStatementKey`, non-empty `asset_id`, accession/content_version |
| P1-4 statement/item currency mismatch | Closed | reject mismatch without explicit FX; explicit FX updates statement and items |
| P2-1 item/unit kind mismatch | Closed | model-level equality validation |
| P2-2 inconsistent item periods | Closed | when present, item period must match statement period |
| P2-3 empty FX metadata | Closed | `rate_date`, `rate_source`, and `rate_version` required |
| P2-4 lexical accession ordering | Closed | registry preserves registration order |
| P2-5 source version missing source document | Closed | `source_version` includes `source_document_id` |
| P2-6 implicit yoy base | Closed | lineage records explicit `yoy_index_base=100` |
| P2-7 mutable canonical models | Closed | `FinancialLineItem` and `FinancialStatement` are frozen |
