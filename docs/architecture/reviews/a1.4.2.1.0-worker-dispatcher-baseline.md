## 2. Existing worker interface

| Item | Current implementation | V1 use | V2 use | Compatibility risk |
|---|---|---|---|---|
| Worker input | `PythonExecutionRequest` in `execution/models.py` | `_Session.run_code` builds request | `PythonTaskExecutor.execute` builds request | Contains `namespace`; fork mode intentionally retains unpicklable values |
| Worker output | `PythonExecutionResult` | maps to user-facing string and workspace artifacts | maps to `ExecutionResult` and artifact recorder | Errors are broad strings at public boundary |
| Namespace state | `dict[str, Any]`; fork keeps non-reserved values; spawn keeps picklable values | `session.ns` | `runtime.execution_namespace` | Cross-container impossible; future Job Contract must use explicit serializable state |
| Timeout | `timeout_seconds`, deadline polling, SIGTERM then SIGKILL | `_CODE_TIMEOUT` | request timeout | Must remain backend-owned for process backend |
| Cancellation | `asyncio.Event` from API, propagated as `cancel_event` | checked at stream/event boundaries | passed through `cancel_event_provider` | Existing event cannot be serialized into future Job |
| stdout/stderr | captured in worker `StringIO`, trimmed by `max_output_chars` | returned in `result.output` | `stdout_preview` | Bounded; preserve size semantics |
| Artifact discovery | workspace diff, excludes dot directories, size check | parent scans `files_after - files_before` | worker result plus recorder | No independent symlink/type validation yet |
| State transfer | result queue for small values; workspace pickle for large values | updates `session.ns` | updates runtime namespace | Worker crash may leave `.python_state_*.pkl` in parent-crash cases |
| Error propagation | `BaseException` caught in worker, result status `failed`; parent maps timeout/cancel | user-facing `[ERROR]` | `ExecutionResult.error` | Must distinguish infrastructure and code errors in new contract |

## 3. Worker lifecycle

- `IsolatedPythonExecutor.__init__` chooses `fork` when available, otherwise `spawn` (`python_executor.py:229-233`).
- One `multiprocessing.Process` is created per `execute` call (`:252-256`).
- Worker calls `os.setsid()` and clears `os.environ` (`:137-148`).
- Optional `RLIMIT_AS` is applied only when `max_memory_mb` is supplied (`:150-156`). Current V1/V2 callers do not set it.
- Parent polls cancellation every 0.1 seconds (`:264-270`).
- On timeout/cancel, parent sends `SIGTERM` to the worker process group, waits 5 seconds, then `SIGKILL` and waits 2 seconds (`:271-303`).
- State file is removed on timeout/cancel and normal completion (`:289-290`, `:324`).
- Artifact size violation deletes the offending file and raises `OSError` in worker (`:193-205`).

## 4. Cancellation and timeout compatibility contract

The A1.2/A1.3 cancellation behavior is treated as frozen compatibility:

1. API cancel creates and sets `asyncio.Event` in `_ACTIVE_CANCELS`.
2. Runtime V1 checks cancellation at stream/event boundaries.
3. Runtime V2 provides the session cancellation event to `PythonTaskExecutor`.
4. `IsolatedPythonExecutor` polls the event during worker execution.
5. Cancellation and timeout both terminate the process group.
6. Repeated cancellation is idempotent.
7. Cancel during completion remains an observable runtime cancel; existing tests codify this behavior.

Relevant tests:

- `tests/test_isolated_python_executor.py`
- `tests/runtime_v2/test_a132_linux_worker_validation.py`
- `tests/runtime_v2/test_runtime_v2_cancellation.py`
- `tests/runtime_v2/test_runtime_e2e.py`
- `tests/runtime_v2/test_runtime_v2_sse_streaming.py`

Known limitation: tests prove ordinary same-process-group child termination. They do not prove that an adversarial double-forked `setsid` descendant cannot survive. This cannot be resolved by the dispatcher abstraction alone and remains for the container isolation phase.

## 5. Existing security posture

The current executor is **bounded process execution**, not a sandbox:

- environment cleanup prevents direct `os.environ` access;
- Python audit hook blocks direct workspace-external `open()`;
- subprocess/native modules can bypass the audit hook;
- fork can expose parent heap/module globals;
- no network egress restriction exists in production;
- production container lacks hardening and resource limits.

These findings are inherited from A1.4.2.0. A1.4.2.1 must not weaken them or advertise stronger security.

## 6. Requirements for the new abstraction

1. Keep `IsolatedPythonExecutor` as the real process implementation; do not duplicate worker execution logic.
2. Introduce serializable `WorkerJob` and `WorkerResult` models.
3. Keep process-only namespace state as an explicit compatibility field until container work defines a portable state mechanism.
4. Preserve existing timeout and cancellation behavior through a process backend adapter.
5. Define a Docker backend interface/placeholder only. It must fail closed and must not create containers.
6. Default backend is `process`.
7. Unknown or unimplemented backend selection must produce an explicit error, never a silent fallback.
8. Job Contract must not carry API secrets, RuntimeContext, LLM clients, DB connections, callables or raw multiprocessing events.
9. Do not log complete user code.

## 7. Explicit non-goals for A1.4.2.1

- No Docker socket access.
- No container creation.
- No production Docker routing.
- No network isolation implementation.
- No independent filesystem sandbox.
- No replacement of Python audit hook or workspace rules.
- No change to Runtime V2 default switch.
- No change to Agent prompt, Evidence contract, planner, report or B11 contracts.

## 8. Implementation risks

| Risk | Mitigation |
|---|---|
| Accidentally replacing rather than adapting existing executor | Process backend must wrap `IsolatedPythonExecutor.execute` |
| Breaking cancellation race semantics | Reuse existing cancellation tests and add dispatcher-level race tests |
| Job Contract becoming Python-object bag | Strict Pydantic model and serialization tests; no `Any` payload for runtime objects |
| Silent Docker fallback | Docker backend `execute` raises unsupported; factory errors on invalid backend |
| Duplicate concurrency/cancel registries | Do not duplicate API `_ACTIVE_CANCELS`; dispatcher owns only its own job handle |
| Artifact behavior regression | Preserve workspace diff semantics and existing recorder integration |
| Security overstatement | Documents must explicitly say Process Backend remains non-sandbox |
