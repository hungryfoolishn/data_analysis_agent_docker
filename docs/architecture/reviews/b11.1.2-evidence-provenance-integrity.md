# B11.1.2 Evidence Provenance and Output Integrity

Status: complete
Baseline: `472f86febbc5469769c1ead0531e7894b9cd6689`
Scope: strict evidence-to-execution association, SQLite snapshot integrity, and output asset requirements.
B11.2.0 / output asset binding was not started.

## Fixes

### 1. Execution association is no longer existence-only

`EvidenceRegistry.validate_references()` now checks that the referenced execution:

- exists;
- has the same `task_id` as the evidence;
- has the same `tool_name` as the evidence;
- has terminal status `succeeded`.

Therefore evidence cannot borrow an unrelated real execution ID.

### 2. Canonical content validation requires provenance

`AnalysisRuntime._validate_canonical_evidence_content()` now dispatches by evidence type.

For `analysis_operation`, verification fails unless evidence has:

- at least one input asset;
- exactly one output asset;
- at least one artifact;
- `row_count`;
- `column_count`.

It also checks that the output asset:

- exists;
- records the same `execution_id`;
- has matching output row count;
- has matching output column count;
- and that referenced artifacts exist and belong to the same execution.

For `sqlite_query`, verification fails unless evidence has:

- input assets;
- exactly one output asset;
- non-empty `query_fingerprint`;
- `source_asset_id`;
- source asset included in `input_asset_ids`;
- `returned_row_count`.

The output asset must:

- have `source_type="sqlite"`;
- have `location=None`;
- record the same execution ID;
- contain a snapshot reference;
- include snapshot ID and hash;
- include snapshot `row_count`;
- match evidence `returned_row_count`;
- match output asset schema row count.

`legacy` evidence cannot be verified from execution metadata alone. It requires a future explicit validator.

### 3. SQLite output records execution provenance

`AnalysisRuntime.register_sqlite_result()` now accepts `execution_id`.
`SQLiteQueryTool` passes the real execution ID into the output asset metadata.
Content validation uses that metadata to ensure the output was produced by the same execution.

## Tests

Added cases:

- wrong task ID fails;
- wrong tool name fails;
- failed execution fails;
- operation evidence without output asset fails;
- operation evidence without row_count fails;
- SQLite evidence without snapshot reference fails;
- SQLite snapshot without row_count fails;
- SQLite returned row count mismatch fails.
