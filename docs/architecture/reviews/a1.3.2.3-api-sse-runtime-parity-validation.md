### 3.3 V2 Expected Differences (by design)

1. **S1.report_content_streamed**: V2 emits structured operation results (`{"status": "succeeded", "operation": "inspect"...}`) plus a structured report. The report does not contain the literal "Regional sales report" title from the fake LLM REPORT constant.
2. **S1.ground_truth_in_stream**: V2 streams the report structure but not the raw numeric values (220/80). These are stored in the output parquet DataAsset.
3. **S2.single_agent_execution**: V2 uses a deterministic planner and makes zero LLM calls. `llm_calls=0` is correct.
4. **S4.cancel_streamed**: V2 analysis completes too fast for cancel to take effect mid-run.
5. **S1.report_head_before_tail**: Same reason as #1 — different report format.

## 6. Limitations

1. **V2 cancel parity**: The S4 cancel test in V2 mode trivially passes because V2 is fast enough to complete before cancel is sent. Mid-operation cancel in V2 is not tested here (deferred to A1.3.2.5).
2. **LLM calls after disconnect (S5)**: V1 shows 2 calls after disconnect before the cancel event propagates. This is within the expected range (max=6) but shows a small delay before cancellation fully takes effect. The server-side `cancel_event.set()` mechanism (api_server_langgraph.py) works but has async latency.
3. **findings table is empty**: V2 deterministic mode does not produce LLM-generated findings. Findings generation is a V1 behavior.
