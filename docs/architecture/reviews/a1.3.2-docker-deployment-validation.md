## 9. Remaining Risks and Limitations

### P2 Items (non-blocking, production hardening)
1. **N1 public internet not blocked**: Docker bridge default allows outbound. Recommend network ACL or egress proxy for production.
2. **content_hash not re-verified on read**: Hash stored at creation, not checked when serving artifacts post-restart.
3. **E5 no evidence re-verification pipeline**: Evidence status preserved but not actively re-validated.
4. **Dashboard test harness auth gap**: 2 tests fail due to 401 auth (pre-existing, not introduced by A1.3.2).
5. **max_memory_mb not wired (A1.2-5)**: Worker RLIMIT_AS code exists but caller does not pass the parameter. Container memory limit (4GB) is the effective control.

## 10. Not Verified Items

1. **Real LLM API integration**: Tests use fake LLM server; no real API call verification in this phase.
2. **Production load**: No load testing performed.
3. **Multi-container deployment**: Single container tested only.
4. **Docker Swarm/K8s orchestration**: Not tested.
5. **TLS/HTTPS**: API tested on HTTP only.

## 11. Gate Decisions

### A. Docker Deployment Readiness: **PASS WITH LIMITATIONS**

The Docker environment correctly deploys, runs, and isolates the application. All critical security boundaries (memory, PID, CPU, filesystem, privilege) are enforced. The P2 limitations (N1 network, E4/E5 evidence hardening) are deployment-level concerns.

### B. Runtime V2 Technical Readiness: **PASS WITH LIMITATIONS**

V2 works correctly in the Docker environment with deterministic planner, structured output, and proper evidence chains. V1↔V2 rollback is clean and reversible. V2 failure semantics are strict stop (no auto-fallback). The limitation is that V2 does not produce LLM-generated findings (deterministic mode only).

### C. Real User Canary Readiness: **NO-GO**

Real user canary requires:
1. Real LLM API integration testing (not done)
2. Production-grade network isolation (N1 not blocked)
3. Evidence re-verification pipeline (E5 not implemented)
4. Load testing (not done)
5. TLS/HTTPS termination (not tested)
6. Monitoring and alerting setup (not verified)

These conditions are not met in the current validation scope. Canary rollout should not proceed until the above items are addressed.
