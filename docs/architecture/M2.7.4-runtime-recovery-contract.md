# M2.7.4: SQLite Snapshot Recovery Contract

## 目标

B2 / M2.7.4 验证 SQLite 查询结果资产可以跨 Runtime 实例恢复，并继续被执行链路消费。
本阶段不新增核心功能，重点覆盖注册 -> 持久化 -> 重启 -> 恢复 -> 解析 -> 执行。

## 恢复链路

```text
SQLiteDataSource.execute_bounded_query()
  -> BoundedReadResult
  -> AnalysisRuntime.register_sqlite_result()
     -> SnapshotStore.save()
     -> DataAsset.source_metadata["snapshot_reference"]
     -> AnalysisRuntime._persist()
  -> Runtime instance destroyed
  -> new AnalysisRuntime(workspace_dir, session_id, question)
     -> .analysis_runtime.json restore
     -> DataAsset / task.input_asset_ids restore
  -> AssetResolver.resolve(asset_id)
     -> SnapshotStore.load(reference)
     -> physical hash + logical content hash verification
  -> TaskExecutionRequest.namespace.runtime_inputs
  -> Executor
```

## 恢复契约

### 稳定字段

重启后必须恢复：

- `asset_id`
- `source_type == "sqlite"`
- `location is None`
- `content_hash`
- `source_metadata`
- `snapshot_reference`
- `source_identity`
- `query_fingerprint`
- `query_type`
- `table_name`
- `selected_columns`
- `row_count`
- `truncated`
- `task.input_asset_ids`

### 消费规则

- Runtime 重建时必须创建新的实例，不能复用旧进程内存。
- 解析时必须通过 `AssetResolver` 和 `SnapshotStore.load()`。
- 物理快照 SHA-256 和 DataFrame content hash 必须都通过。
- 不允许重新执行 SQLite SQL 来恢复数据。
- 不允许快照缺失或损坏时静默跳过输入。

## 失败语义

| 场景 | 行为 |
| --- | --- |
| 快照文件删除 | `AssetResolutionError`，明确失败 |
| 快照物理 hash 不匹配 | `AssetResolutionError`，明确失败 |
| SnapshotReference 无效 / 版本不兼容 | `AssetResolutionError`，明确失败 |
| 快照路径越界 | `AssetResolutionError`，明确失败 |
| Runtime 元数据损坏 | 不恢复 assets；解析时 `AssetNotFoundError` |
| 元数据存在但快照缺失 | `AssetResolutionError`，明确失败 |
| 复用资产但 task 关联持久化失败 | 回滚新增 task 关联，保留已有快照 |

错误信息不得暴露 SQLite 数据库路径或 snapshot 绝对路径。

## 测试

`tests/test_runtime_sqlite_recovery_e2e.py` 覆盖：

- Golden SQLite 注册 -> 重启 -> Resolver 加载 -> Python executor 执行
- 重启后重复加载
- 重启后重复注册 / dedupe
- 快照删除
- 快照物理 hash mismatch
- SnapshotReference 无效
- Runtime metadata 损坏
- 复用资产 task 关联持久化失败且快照保留
- 删除源 SQLite 文件后仍可执行快照分析
