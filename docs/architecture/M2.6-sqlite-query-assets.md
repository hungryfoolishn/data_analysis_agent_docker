# M2.6: SQLite 查询结果接入 Runtime V2 DataAsset

## 范围

M2.6 将 M2.5 的 `BoundedReadResult` 注册为 Runtime V2 可持久化 DataAsset。
本阶段只处理来源身份、query provenance、DataFrame 内容指纹、资产注册、task input
关联和最小去重；不接入 Evidence、Findings、Report Claims，也不引入 SQL Agent。

## 来源身份

`SQLiteConnectionConfig` 新增可选 `source_identity`。未配置时，
`SQLiteDataSource.source_identity` 使用规范化数据库路径的 SHA-256：

```text
sqlite:sha256:<64 hex characters>
```

该身份在重复打开同一数据库时保持稳定。资产 metadata 只保存稳定身份，不保存
数据库路径。

## Query provenance

`SQLiteReadMetadata` 新增：

- `source_identity`
- `query_type`: `table` 或 `sql`
- `query_sha256`

`query_sha256` 由 normalized SQL、参数指纹和 query mode 组成：

- SQL 只做空白归一化，不改写语义。
- tuple 和 mapping 参数分别进入指纹。
- 不保存原始参数值。
- table read 和 SQL query 可区分。

`DataAsset.source_metadata` 保存 `source_identity`、`query_fingerprint`、
`query_type`、`table_name`、`selected_columns`、`row_count` 和 `truncated`。
原始 SQL、原始参数和数据库路径不写入 DataAsset。

## DataFrame 内容指纹

`hash_dataframe()` 对以下内容做 canonical SHA-256：

- schema version
- 列名与列顺序
- pandas dtype
- 行数与行顺序
- NULL/NaN/NaT
- bool、整数、浮点数、文本、bytes、Decimal、date/time/datetime/timedelta

不支持的对象值会抛出 `TypeError`，不会静默使用不稳定 repr。

## DataAsset 兼容扩展

`DataAsset.location` 变为 `Optional[str]`。文件来源继续保存真实路径；SQLite 查询
来源使用：

```text
source_type = "sqlite"
location = None
content_hash = hash_dataframe(result.dataframe)
source_metadata = structured query provenance
```

不通过把 SQL 或数据库路径写成假文件路径来兼容旧模型。

## Runtime 接入

`AnalysisRuntime.register_sqlite_result(result=...)`：

1. 校验 `BoundedReadResult` 中的 SQLite provenance。
2. 计算 DataFrame content hash。
3. 创建或复用 DataAsset。
4. 将 asset 关联到当前 `task.input_asset_ids`。
5. 通过现有 `_persist()` 持久化。
6. 持久化失败时回滚新增 asset 和 task 关联。

## 去重语义

只有 `source_type=sqlite`、`content_hash` 和完整 `source_metadata` 都相同的资产
才会复用。因此：

- 同 provenance + 同内容：复用已有资产。
- 不同 provenance + 同内容：保留不同来源记录。
- 同 provenance + 不同内容：创建新资产。
- 复用资产时，当前 task 仍会正确关联该资产。

## M3 / Evidence 边界

M2.6 不生成 Evidence 或 Finding。Runtime 后续证据链路可以引用这里的
`asset_id`、`content_hash` 和 `source_metadata`，但证据判定仍属于后续阶段。
