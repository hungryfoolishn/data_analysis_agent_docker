# M2.7.3: AssetResolver 与 SQLite 快照消费

## 范围

B1 / M2.7.3 只实现已注册 SQLite 查询结果快照的消费。不重新执行 SQL，不实现
通用 Planner、SQL Tool、Evidence、报告生成或 Runtime 默认切换。

## AssetResolver

新增模块：

```text
langgraph_langchain/runtime/asset_resolver.py
```

公开接口：

```python
class AssetResolver:
    def resolve(self, asset_id: str) -> ResolvedAsset: ...
    def resolve_many(self, asset_ids: Sequence[str]) -> dict[str, ResolvedAsset]: ...
```

`resolve_many()` 保持调用顺序，返回以 `asset_id` 为 key 的映射；重复 ID 只解析一次。

`ResolvedAsset` 保留：

- `asset_id`
- `dataframe`
- `source_type`
- `source_identity`
- `query_fingerprint`
- `query_type`
- `table_name`
- `selected_columns`
- `row_count`
- `truncated`
- `snapshot_reference`
- `provenance`

## 错误契约

- `AssetNotFoundError`：asset ID 未注册或为空。
- `AssetUnsupportedError`：不是 SQLite snapshot-backed asset，或 snapshot
  reference 缺失 / 无效。
- `AssetInputConflictError`：执行 namespace 已占用保留键。
- `AssetResolutionError`：SnapshotStore 加载失败后的稳定归一化错误。

Resolver 不返回未通过校验的数据。SnapshotStore 负责物理 SHA-256 与
DataFrame content hash 双重校验。错误信息不包含数据库路径或 snapshot 绝对路径；
原始异常保留在服务端异常链中。

## Runtime 请求注入

`AnalysisRuntime.build_execution_request()` 会在 task 有 `input_asset_ids`
时调用 resolver，并注入两个保留 namespace 键：

```python
runtime_inputs = {
    "<asset_id>": <pd.DataFrame>,
}

runtime_input_metadata = {
    "<asset_id>": <ResolvedAsset.provenance>,
}
```

使用 `asset_id` 作为唯一 key，避免多个资产同名时静默覆盖。请求构建使用
`self.execution_namespace` 的拷贝，不修改 Runtime 全局 namespace。

如果已有 `runtime_inputs` 或 `runtime_input_metadata`，解析失败为
`AssetInputConflictError`。解析失败不会跳过输入，也不会 fallback 重新执行 SQL；
`TaskExecutionRequest.metadata["asset_resolution_error"]` 记录稳定错误类型和消息，
`TaskExecutor` 将其转换为 failed `ExecutionResult`。

## 安全与一致性

- 只消费已登记 DataAsset 中经过 SnapshotStore 校验的 snapshot reference。
- 不接受用户路径作为快照位置。
- 不重新执行 SQL。
- 不使用 RuntimeArtifact 承载输入快照。
- 不把 DataFrame 写入 Runtime 元数据 JSON。
- 保留 `truncated`、row count、query fingerprint、source identity 等后续
  Evidence 需要的 provenance。
