# A1.4.2.2.2 — Filesystem & Artifact Isolation Implementation Plan

## Scope

Build the Docker Worker filesystem and artifact boundary required after A1.4.2.2.1, without changing the default Process Backend, Runtime V2 default switch, Runtime public contracts, or B11 frozen contracts.

## Non-Goals

- Network and secret isolation (A1.4.2.2.3).
- Production enablement of the Docker Worker backend.
- A second Evidence system or changes to B11 APIs.
- Full filesystem-level disk accounting or user-level quotas.

## Design Decisions

1. Unified relative-path validation in `langgraph_langchain/execution/path_safety.py`.
2. Per-job, manager-owned workspace outside the old shared workspace model:
   - root: `/tmp/deepanalyze-worker-jobs/<job_id>`
   - `input/`, `output/`, `tmp/`, `collected/`
   - atomic `manifest.json` with job identity and input hashes
3. Workspace reuse is forbidden. A duplicate creation must fail.
4. Inputs are copied rather than hardlinked and are verified before outputs are accepted.
5. Containers receive only:
   - `/workspace/input:ro`
   - `/workspace/output:rw`
   - `/workspace/tmp:rw` when supplied
6. Outputs are collected into a two-phase, all-or-nothing `collected/` directory with explicit validation.
7. Cleanup is job-id bound and refuses unmanaged or identity-mismatched roots.

## Implementation Plan

| Step | Area | Key symbols |
|---|---|---|
| 1 | Path safety | `PathSafetyError`, `validate_relative_path`, `safe_workspace_join`, `is_safe_published_filename` |
| 2 | Workspace lifecycle | `ContainerManager.create_workspace`, `JobWorkspace`, `_write_manifest_atomic`, `cleanup_workspace` |
| 3 | Input integrity | `verify_input_integrity` |
| 4 | Output publishing | `publish_artifacts`, `collect_output_files` |
| 5 | Docker backend integration | `DockerWorkerBackend._execute` |
| 6 | Image and entrypoint | `docker/worker/Dockerfile.worker`, `worker_entrypoint.py` |
| 7 | Tests | unit, manager/backend, and real-container isolation tests |

## Same-Context Review Disclaimer

This phase was implemented and reviewed in the same working context. The independent-review document records a same-context independent recheck, not a separate-author audit.

## Production Status

Production use is not approved. The Docker backend remains a selectable backend, not the default.

## Disk Quota Status

Output collection caps are enforced. Filesystem-level or job-user disk quotas are not yet implemented and remain explicitly unverified.
