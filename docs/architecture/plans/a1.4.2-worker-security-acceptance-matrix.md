# A1.4.2 — Worker Security Acceptance Matrix

- Date: 2026-11-20
- Stage: A1.4.2.0 design baseline
- Rule: a configured file alone is not acceptance evidence. Every security control must be tested in an isolated Docker environment.

## 1. Environment and evidence rules

Required evidence classes:

| Symbol | Meaning |
|---|---|
| CONFIG | inspect compose/Dockerfile/container metadata |
| RUNTIME-POSITIVE | authorized business functionality succeeds |
| RUNTIME-NEGATIVE | unauthorized access or bypass fails |
| E2E | V1/V2 complete workflow succeeds |
| ROLLBACK | safe rollback/legacy path proven |
| AUDIT | independent review confirms evidence and scope |

Acceptance environment requirements:

- dedicated Docker Compose project name, network, volumes and ports;
- no reuse of production project, production network or production volumes;
- no modification of production container, host firewall or sysctl during tests;
- test network and job containers must be removed after acceptance;
- adversarial tests must not scan unrelated external systems.

## 3. Detailed acceptance criteria

### 3.1 Job Contract and dispatch

| ID | Acceptance criterion |
|---|---|
| JC-1 | Runtime V1 and V2 can call the dispatcher through the same backend interface. |
| JC-2 | Job Contract rejects missing `job_id`, `session_id`, `execution_id`, code, workspace policy or resource limits. |
| JC-3 | Host paths are generated only by dispatcher and validated before container creation. |
| JC-4 | Worker job contains no API/DB/LLM credentials or unrelated environment. |
| JC-5 | Concurrent jobs do not share a job input/output directory. |
| JC-6 | Dispatcher enforces a configured global concurrency ceiling. |

### 3.2 Container security

| ID | Acceptance criterion |
|---|---|
| CS-1 | Worker runtime user is non-root and no process in worker runs as root. |
| CS-2 | Root filesystem is read-only or image is proven immutable. |
| CS-3 | Capabilities are `ALL` dropped; only documented minimal additions are present. |
| CS-4 | `no-new-privileges:true` is effective. |
| CS-5 | Curated seccomp profile is effective and documented. |
| CS-6 | No Docker socket, host root, application code, config or official artifact volume is mounted. |
| CS-7 | Runtime container metadata and live `/proc` inspection agree. |

### 3.3 Filesystem and artifact

| ID | Acceptance criterion |
|---|---|
| FS-1 | Job inputs are mounted read-only. |
| FS-2 | Worker can write only its output directory and ephemeral temp. |
| FS-3 | Output path validation rejects `..`, absolute path escape and symlink. |
| FS-4 | Parent copies and hashes approved files after validation. |
| FS-5 | Oversized or excessive files fail before official registration. |
| FS-6 | Failed/cancelled output is removed unless partial-output policy is explicitly enabled. |
| FS-7 | Startup reaper removes stale job containers/directories from a prior parent crash. |

### 3.4 Network

| ID | Acceptance criterion |
|---|---|
| NET-1 | Default egress is deny for IPv4 and IPv6. |
| NET-2 | DNS cannot resolve or connect to unauthorized destinations beyond explicit policy. |
| NET-3 | Proxy variables are absent and cannot cause a bypass. |
| NET-4 | Host gateway access is denied unless explicitly authorized. |
| NET-5 | Unauthorized container and database connections fail. |
| NET-6 | Policy persists across worker restart and host/container service restart where applicable. |

### 3.5 Resource, timeout and cancellation

| ID | Acceptance criterion |
|---|---|
| RC-1 | CPU quota is observed. |
| RC-2 | Memory allocation beyond limit fails without OOM-killing the host/API. |
| RC-3 | PID limit stops fork loops. |
| RC-4 | Output bytes/file count limits stop storage exhaustion. |
| RC-5 | Timeout triggers SIGTERM then SIGKILL/container kill. |
| RC-6 | Cancel API maps to dispatcher stop and returns `cancelled`. |
| RC-7 | No descendant process remains after timeout/cancel. |
| RC-8 | Cleanup failure is recorded and does not leave an active worker silently. |

### 3.6 Runtime compatibility

| ID | Acceptance criterion |
|---|---|
| RT-1 | V1 ReAct session completes with container worker backend. |
| RT-2 | V2 explicit opt-in session completes with container worker backend. |
| RT-3 | Existing CSV/Excel/Parquet/SQLite workflows produce expected artifacts. |
| RT-4 | Python failure, timeout, cancel and container crash map to existing user-visible statuses. |
| RT-5 | Artifact registration and Evidence contract remain unchanged at runtime boundary. |
| RT-6 | `RUNTIME_V2_ENABLED` default remains unchanged by this work. |
| RT-7 | Rollback switch affects only new jobs; active jobs are drained. |
