# A1.4.2.2 — Docker Worker Implementation Roadmap

Planning basis: HEAD `4d322cc`. Process Backend remains the default; Docker Backend is explicit opt-in only; production enablement is NOT approved in any phase below until the final gate.

## A1.4.2.2.1 — Docker Worker Container Foundation

- **Scope**: `Dockerfile.worker` (pinned, non-root); `ContainerManager` (create/start/stop/kill/rm, labels, reconciliation scan); `DockerWorkerBackend` implementing `WorkerBackend` with JSON job envelope (`job.json`) and result protocol (`result.json`); explicit backend selection wiring (env `WORKER_BACKEND=docker` or constructor), validated names only, no silent fallback.
- **Non-goals**: network isolation hardening, artifact transfer policy beyond minimal staging, resource-limit tuning.
- **Tests**: backend contract tests (envelope round-trip, fail-closed without daemon, cancel lifecycle), container create/remove against a disposable test daemon, V1/V2 dispatcher contract tests with Docker backend stub replaced by fake manager.
- **Security acceptance**: S10 (no socket in worker), S20 (no residual container), T18 fail-closed behavior.
- **Rollback**: `WORKER_BACKEND=process` / unset; no data migration.
- **Gate**: container lifecycle reliable; dispatcher contract unchanged; process default untouched.

## A1.4.2.2.2 — Filesystem & Artifact Isolation

- **Scope**: input staging (copy to job dir, RO mount), output dir per job, tmpfs `/tmp`, read-only rootfs, host-side artifact validation reuse (symlink/escape/size/extension/sha256), state handoff policy decision (stateless-per-job default).
- **Tests**: S01–S04, S19; artifact tamper test; large-file quota tests.
- **Rollback**: mount configuration revert; backend remains opt-in.
- **Gate**: all filesystem isolation tests pass; originals unmodifiable.

## A1.4.2.2.3 — Network & Secret Isolation

- **Scope**: `--network none` default; verify IPv4/IPv6/DNS/proxy/host access denial; environment allow-list delivery; no env_file/secret mounts.
- **Tests**: S05–S09 using dedicated in-container test probes (no external scanning).
- **Rollback**: network flag revert.
- **Gate**: network matrix fully denied for default policy.

## A1.4.2.2.4 — Resource & Cancellation Hardening

- **Scope**: cpu/memory/pids limits; timeout -> stop(t=10s)->kill->rm sequence; orphan reconciliation; cleanup-failure recording; cancel-during-each-lifecycle-stage tests.
- **Tests**: S11–S18; fork-bomb probe; host-restart reconciliation test.
- **Rollback**: limits are per-container flags; revert = redeploy.
- **Gate**: cancellation confirmed only after container removal; no orphans after restart simulation.

## A1.4.2.2.5 — Security Attack Tests

- **Scope**: adversarial suite: traversal, symlink, socket access attempt, egress attempts, resource exhaustion, artifact tampering, result-protocol abuse (T16).
- **Tests**: full S-matrix execution with evidence.
- **Gate**: all S01–S20 PASS or documented accepted-risk with justification.

## A1.4.2.2.6 — Runtime E2E & Rollback

- **Scope**: V1 + V2 against Docker backend (explicit opt-in), SSE, cancellation, timeout, artifact flow e2e; process-vs-docker parity on job semantics (excluding namespace continuity); rollback drill (switch back to process mid-flight).
- **Tests**: existing runtime suites re-run with Docker backend profile.
- **Gate**: no V1/V2 regressions; rollback drill successful.

## A1.4.2.2.7 — Independent Security Review

- **Scope**: architecture vs implementation diff review, threat model verification, docker config review, S-matrix evidence review, production readiness decision.
- **Gate**: independent verdict; only then is `Docker Production Enablement` even proposed for approval.

## Production Enablement Gate (after .7)

Separate explicit approval required: deployment config change, `WORKER_BACKEND=docker` in production compose, rollback plan rehearsed. This phase (A1.4.2.2.0) does NOT approve production enablement.

## Commit discipline (applies to every phase)

- No `git add .`; precise paths only; staged diff review; no force push; no amend.
