# M2.7.2: SQLite DataAsset SnapshotStore

## 范围

M2.7.2 为 M2.6 注册的 SQLite 查询结果 DataAsset 增加不可变数据快照持久化能力。
本阶段不实现 AssetResolver，不接入 Runtime Executor，不生成 Evidence 或 Finding，
也不切换 Runtime V2 默认行为。

## 存储设计

新增模块：

```text
langgraph_langchain/data/snapshots.py
```

默认存储根目录：

```text
<workspace>/.data_snapshots/
```

快照文件命名：

```text
<snapshot_id>.parquet
```

`snapshot_id` 使用：

```text
snap_<32 lowercase hex characters>
```

SnapshotStore 只接受自己生成的 store-relative 路径，拒绝 `..`、绝对路径和
root 外路径。保存使用同一文件系统临时文件 + `os.replace()` 原子替换，并执行
file fsync；目录 fsync 为 best-effort。

## SnapshotReference

`SnapshotReference` 保存：

- `snapshot_id`
- `snapshot_format`
- `snapshot_location`
- `snapshot_hash`
- `snapshot_hash_type`
- `content_hash`
- `row_count`
- `column_count`
- `created_at`

两个哈希语义不同：

- `snapshot_hash`：Parquet 物理文件的 SHA-256。
- `content_hash`：`hash_dataframe()` 计算的 DataFrame 逻辑内容哈希。

`DataAsset.location` 仍然保持 `None`，不表示 SQLite 数据库路径。快照引用写入：

```text
DataAsset.source_metadata["snapshot_reference"]
```

## SnapshotStore 行为

`SnapshotStore` 提供：

- `save(dataframe, snapshot_id=..., content_hash=...)`
- `load(reference)`
- `exists(reference)`
- `delete(reference)`

`save()` 会：

1. 校验输入是 DataFrame。
2. 计算 `hash_dataframe()`。
3. 拒绝覆盖已有 snapshot ID。
4. 写入 Parquet 临时文件。
5. fsync 并读取临时文件验证 shape 与 content hash。
6. 计算物理文件 SHA-256。
7. 原子替换到 final path。
8. 返回 `SnapshotReference`。

`load()` 会：

1. 校验 snapshot ID、format、hash type 和 store-relative path。
2. 验证路径位于 SnapshotStore root 内。
3. 检查文件存在。
4. 校验物理文件 `snapshot_hash`。
5. 读取 Parquet。
6. 校验 row count / column count。
7. 重新计算 `hash_dataframe()` 并校验 `content_hash`。
8. 全部通过后才返回 DataFrame。

`exists()` 只检查文件是否存在，不做完整性校验。`delete()` 只能删除该 store
管理、且路径校验通过的快照。

## Runtime 注册集成

`AnalysisRuntime` 新增可选 `snapshot_store` 参数。未传入时默认使用：

```python
SnapshotStore(workspace_dir / ".data_snapshots")
```

`register_sqlite_result()` 的新流程：

1. 校验 SQLite bounded read provenance。
2. 计算 DataFrame `content_hash`。
3. 先检查是否已有同 provenance + 同 content 的 DataAsset。
4. 可复用时验证已有 snapshot reference 存在；缺失时显式失败。
5. 新资产先保存快照。
6. 再创建 DataAsset，并把 snapshot reference 写入 source metadata。
7. 关联 `task.input_asset_ids`。
8. `_persist()` 持久化 Runtime 元数据。
9. Runtime 元数据持久化失败时删除本次新建快照并回滚 asset / task 关联。
10. 复用已有快照时不会删除已有快照。

不会重新执行 SQL 来恢复或补齐快照。

## 测试覆盖

`tests/test_snapshot_store.py` 覆盖：

- save/load round-trip
- 空表、NULL、日期、nullable integer、布尔、字符串、重复行
- snapshot hash mismatch
- content hash mismatch
- missing snapshot
- corrupt snapshot
- unsupported format
- path traversal
- failed write cleanup
- no silent overwrite
- wrong content hash
- delete safety

`tests/test_runtime_sqlite_query_asset.py` 扩展覆盖：

- 注册后 snapshot reference 存在并可加载
- Runtime 重启后引用恢复
- dedup 复用快照
- 不同内容创建新快照
- SnapshotStore.save 失败不登记 asset
- Runtime persist 失败清理新快照
- truncated 状态保留

## 已知限制

- 本阶段只提供 SnapshotStore，不提供 AssetResolver。
- Runtime Executor 尚未消费 resolved DataFrame。
- SnapshotStore 只负责注册时的数据快照，不提供通用垃圾回收。
- 不支持的 DataFrame 对象值仍由 `hash_dataframe()` 显式失败。
