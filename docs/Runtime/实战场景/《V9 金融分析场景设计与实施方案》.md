下面这份我按你当前 `data_analysis_agent_docker` 的 **V8.5 实际能力**来设计，不再把重点放在 Skill 自进化，而是把系统正式推进到一个**可验证的金融分析业务场景**。

我建议 V9 的定位明确为：

> **V9 = Financial Analysis Domainization：金融分析领域化**
>
> 不是做“金融聊天机器人”，而是把现有 Data Analysis Runtime 变成一个具备**金融数据语义、指标计算、同业比较、趋势分析、风险发现、证据追溯和专业报告生成**能力的金融分析 Agent。

数据源方面，第一阶段建议以**公开披露的历史财务数据**为主，而不是一开始接实时行情。上交所目前提供上市公司定期报告、公告以及经营业绩概览等数据入口，其中经营业绩概览明确说明数据来自上市公司提交的 XBRL 报告；证监会 2026 年发布的 2025 年度财务报告会计监管报告也说明了上市公司年度财务报告数据和披露质量问题。([上海电力公司][1]) 对美股扩展，可以以后接 SEC 的 Company Facts/XBRL API，其官方 API 提供公司财务报表结构化数据。([美国证券交易委员会][2])

# 1. 项目背景

当前 Runtime V8.5 已经具备较完整的数据分析 Agent 基础设施：

```text

    ↓
Task / Execution
    ↓
Verification
    ↓
Evidence
    ↓
Finding
    ↓
Report
    ↓
TaskEvaluation
    ↓
Golden Evaluation
    ↓
SkillQuality
    ↓

```

V8.5 的重点已经从“能不能执行分析”进入到：

* 能否验证执行结果
* 能否验证数字正确性
* 能否绑定 Evidence
* 能否追踪 Claim 来源
* 能否进行 Golden Evaluation
* 能否衡量 Skill / Executor 的质量

因此 V9 不继续扩展 Runtime 基础设施，而进入真实业务领域。

## V9 的核心目标

将：


```text

```

使系统能够回答真实金融分析问题：

```text

盈利能力如何？
```

# 26. 报告必须区分三类内容

这是金融场景非常重要的一点。

### Fact

```text
2025 年营业收入为 X。
```

### Calculation

```text
同比增长 = (2025 - 2024) / 2024
```

### Interpretation

```text
收入增速较上一年度有所下降。
```

三者不能混在一起。

# 60. 本阶段最终目标

V9 的真正目标不是：

> “让 Agent 看起来更像金融专家。”

而是：

> **把通用 Data Analysis Runtime 变成一个具有金融数据语义、金融指标体系、金融分析 Workflow 和可验证金融研究输出能力的 Agent。**

最终形成：

```text
             DeepAnalyze
                  │
                  ▼
       ┌─────────────────────┐
       │ Financial Research  │
       │       Agent         │
       └──────────┬──────────┘
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      Data      Metrics   Workflow
        │         │         │
        └─────────┼─────────┘
                  ▼
             Runtime V8.5
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
   Verification Evidence Lineage
        │         │         │
        └─────────┼─────────┘
                  ▼
           Financial Findings
                  │
                  ▼
          Research Report
```

**V9 的核心交付物：**

```text
1. Financial Data Schema
2. Financial Metric Registry
3. Financial Task Taxonomy
4. Financial Analysis Workflow
5. Financial Calculation Engine
6. Financial Evidence / Lineage
7. 50 Financial Golden Cases
8. Financial Evaluation
9. Financial Research Report
10. Financial Analysis UI
```

**暂不包含：**

```text
Skill Evolution
GEPA
DSPy
自动交易
股票预测
实时行情
自动投资建议
```

这样做的价值在于：你现在已经花了相当多精力把 **Runtime → Evaluation → Evidence → Golden Dataset** 这一套基础设施做起来，V9 正好应该用一个真实业务领域把它“压测”出来。等金融场景真正跑通，再决定哪些地方需要 Skill、哪些地方需要 Workflow、哪些地方需要更强的 Agent 自优化，会比现在直接做 Skill Evolution 更有价值。

这份方案里，我建议下一步不要直接写代码，而是先把 **V9 Phase 1「金融数据 Schema + 20～30 个核心指标」** 定下来。这个阶段一旦设计错，后面的 Workflow、Golden Case 和 Evaluation 都会跟着返工。
