# 十一、Period 类型

定义：

```python
class PeriodType(str, Enum):
    FY = "FY"
    Q1 = "Q1"
    Q2 = "Q2"
    Q3 = "Q3"
    Q4 = "Q4"
    H1 = "H1"
    H2 = "H2"
    TTM = "TTM"
```

并且不能仅保存：




# 十二、Period Comparison

禁止：

```python
"2025" > "2024"
```

作为金融期间比较的核心逻辑。

统一：

```python
PeriodNormalizer.parse()
```

之后：

```python
FinancialPeriod.order_key()
```

例如：

```text
2025 FY
    ↓
(2025, 4)

2025 Q3
    ↓
(2025, 3)
```

这样：

```text
2025 Q3 < 2025 FY
```

可以稳定判断。

# 十四、Metric Formula Golden

这是 V9.3 最重要的新能力。

V9.2 当前主要验证：

> Runtime 算得对不对。

V9.3 要进一步验证：

> **这个指标的业务公式是否正确。**

---

# 十五、为什么需要 Formula Golden

例如 ROE：

```text
ROE =
Net Profit /
Average Shareholders' Equity
× 100
```

如果代码错误地写成：

```text
ROE =
Net Profit /
Ending Shareholders' Equity
× 100
```

对于很多测试数据：

```text
结果仍然看起来合理。
```

普通 Runtime test 很可能发现不了。

因此需要：

```text
Formula Golden Expected Value
```

即：

> **预先定义正确业务公式以及人工确认的 Expected Value。**

---

# 二十、关键原则：Expected Value 不能调用同一个 MetricEngine

这没有意义。

## V9.3 的核心验收结论

最终不要用“新增了多少代码”来衡量 V9.3，而用下面 5 个问题验收：

1. **换成真实财务数据后，Runtime 是否仍然稳定？**
2. **`2025年度 / FY2025 / 2025-Q4` 是否能正确理解为对应的财务期间？**
3. **单位从亿元/万元/百万元转换后，结果是否仍然正确？**
4. **把 ROE 等核心公式故意改错，Formula Golden 能否把它抓出来？**
5. **最终报告里的一个数字，能否一路追溯到 `Raw Source → Fact → Calculation → Verification → Evidence`？**

如果这 5 个问题全部能够通过，**V9.3 才算真正完成，而不是“又增加了一批测试”。**
